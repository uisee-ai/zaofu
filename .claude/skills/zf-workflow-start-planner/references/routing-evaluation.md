# 路由与上下文的效果评估

仅在评估/改进路由方法时读取。生产决策仍遵循当前 Task、授权、目录和 capability。
测试使用近似措辞、不同意图：讨论/仅规划/已授权实施、清楚的小修复/共享契约未知、
存在可用路线/目录不提供能力、Channel PRD ready/Owner 已明确授权启动。

冻结请求及 source revision、目录快照、当前阶段与能力。评分分别检查：

1. 是否应回答、澄清、跟踪或提出执行方案，而非只核对 route_id。
2. 方案是否覆盖完整目标且实际可用，lane/角色/工具建议是否符合隔离和依赖。
3. 必需参数、来源与批准边界是否保持；未调用 apply 不等于没有错误承诺。
4. 方法是否按相关分支读取；读到 Skill 或 canary 字符串不证明路线正确。

评分 oracle 放在工作目录外。训练/调试与留出案例固定分开，留出答案与成绩不给
改写方法的 agent；再用未见案例做最终检查，避免反复挑最高分产生选择偏差。
固定事实可有多个合理方案，按约束和可观察结果判分，不把个人偏好变成唯一答案。

保持相同预算和权限。记录错误启动、误澄清、不可用能力建议、实际 usage 与重复读取，
按阶段审查读取轨迹；不能把物化包总字节当成已加载上下文。无实际轨迹就记未知。
持平时再试删减或按条件加载；所有 required inputs、验收、安全边界仍须完整执行。
