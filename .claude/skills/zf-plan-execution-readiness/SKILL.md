# Plan Execution Readiness

本方法用于把完整需求转换为可执行计划。它不定义新的 task schema，不写运行态，
不替代 Kernel 的引用、路径、代际及完成证据检查。产物使用现有 Plan、task_map、
矩阵和 Critic verdict；项目语义判断必须附来源，不能变成 Runtime 的项目规则。

## 条款与验收责任

先读当前需求 authority，再对每个 AC 内部的条款审查，不能只统计顶层 AC。
每条应能定位：来源 → 可观察结果 → 行为生产者 → 验证 owner/tier/command →
最早可验证阶段。输入、状态变化、拒绝条件、失败后的观察结果不明确时补规格。
“该章节全部实现”可以作范围索引，不能替代可执行判据。

- 工程盘点、架构决定、环境确认用相应静态/契约验证，不强制生成 UI 旅程。
- 事务回滚、同幂等键不同请求、权限拒绝、删除保存等是运行行为，不能仅由盘点
  文件或接口枚举证明。将行为条款绑定到真正拥有实现和测试的切片。
- 一个 AC 混合前置决定和运行行为时拆开验收责任，保留原需求映射；不以任务名、
  prerequisite 标签、空 journey_ids 豁免整个章节。
- `task_verify` 的局部结果只能依赖本片及已完成前置行为。跨后续切片的结果可以
  保留为 mandatory `candidate_verify`，必须有明确后续生产者和验证时点。
- 条件扩展保留来源、启用决定和未启用范围；只在进入受影响阶段前关闭阻塞决定。
  不为开始工程盘点提前猜测所有产品决定，不把未启用条件写成产品已通过。

## 切片与阶段集成

每片在 Plan 中回答：完成后可演示什么、通过哪个实际入口、依赖哪些已完成行为、
失败后应重做哪一片。模块名、路径项数和 AC 数量不是单独的大小判据。

1. 把一个模块中的独立用户行为分别评估；共享基础契约先建立最小版本，业务契约
   随行为细化。不要先冻结全站全部接口才产生第一条可运行路径。
2. 明确启动/接线所有者，并尽早交付可运行入口。可用稳定的扩展注册协议和各片
   独占注册文件；必须证明真实调用者会加载它们，不新增没有调用者的库。
3. 中间阶段交付读取闭环、状态变化闭环等可观察结果；最终装配负责全量验证。
   不只把原阶段名称放进最终任务，同时把所有集成反馈推到最后。
4. 全图仍遵守写入路径唯一性。多个阶段不能声明同一入口文件的独占所有权，
   即使波次不同；阶段验证任务只拥有自己的 spec/runner/evidence 路径。
5. 单次事务中的多项状态变化保留单一命令所有者，用片内 TDD 验证正常、失败
   回滚、修正和幂等；不能拆成对外可见的部分提交来凑小任务。
6. 只读既有状态与启用新的变更命令分开分析。依赖必须来自实际调用、数据或
   证据生产关系；不因为名字相似或流程图排列就添加依赖。
7. 尊重 owner 明定的任务图。owner 已授权重设计时可以修改受影响 ID、依赖、
   AC 和路径，保留旧新映射及理由；不能以“保持原任务图”阻止已授权修复。

## 正例与反例

| 输入 | 判定与理由 | 修订与可验证结果 |
| --- | --- | --- |
| “记录数据库版本与事务重试策略”由盘点任务生成决定文件 | 合理前置决定；文件可证明决定已记录 | 保留盘点 AC；运行时重试另外由命令切片负责 |
| “同 key 不同请求拒绝，失败回滚”也用 inventory.json 的键存在证明 | 拒绝；文件存在不能证明请求冲突和回滚 | 分别绑定请求冲突与数据库事务测试；保留原条款来源 |
| 一个车辆模块同时有基础读写、保险资料、跨项目调拨 | 多种独立行为，应说明拆分依据 | 分为可演示行为片；调拨保留原子事务所有者 |
| 一次作业必须同时改变库存、设备和流程 | 可保持一个原子命令片 | 片内逐项 RED/GREEN：正常、失败无部分写入、重复请求不重复执行 |
| 首片只能导出函数，第 13 波才接入口 | 集成反馈过晚 | 先有调用者和最小路径，后续行为通过独占扩展文件接入并按阶段验证 |
| 已取消状态只读必须等物理删除功能完成 | 缺乏真实依赖依据 | 只读断言归已有流程片，新取消命令按条件决定另行规划 |

Critic 对正例应说明为何可接受，对反例指出具体条款/任务、来源和最小修订。
计数、关键词匹配或机械预检全绿不能替代上述语义判断。

## 提交前证据

- Plan 保留条款责任、切片结果、集成时点、条件决定及主要反例审查结论。
- task_map 与矩阵 ID/路径/命令保持一致；每项缺口有明确 owner 和 done_when。
- 完整 Plan、矩阵和来源索引通过正式产物引用交接，摘要仅作导读。
- 由独立 Critic 复核，不自批 Plan；实现前没有运行证据是正常计划状态。

验证本方法时，既验证 Planner/Critic 依赖物化，也记录真实样例的语义评审。
物化测试通过只证明方法可读，不能证明任意生成计划都满足这些规则。
