# Epic 与批次的累积复盘

先固定 Goal/需求版本、任务集合、各任务基线与最终集成版本。区间重叠去重，
合并冲突修复单独检查；无法确定归属就缩小结论，不把整个 HEAD 差异算给该 Epic。
复用验收报告、事件/store 投影与 required sidecar，不改 canonical 状态。

按实际风险选择检查项并列出未检查范围：

- 所有 mandatory AC 的最终证据，含任务间真实入口、协议和失败后态。
- 多个任务累积引入的依赖环、跨层调用、重复实现和同一规则的不同解释。
- 文件总体职责与增长；行数/churn 用来定位检查对象，不直接判定设计错误。
- 原始意图与实际行为的双向差异；已批准偏差保留决定和版本，不反复报错。

每个发现都回到原始代码、测试、任务或事件核实，再分成两条行动：

| 本次处理 | 防止再发生 |
| --- | --- |
| 修复、延期或接受；证据、owner、复访条件 | 来源/契约、切片、验证方法或机械约束应如何变化；也可以无需过程变更 |

检查上一次复盘的行动，逐项给出已落地证据、已证实未完成，或“未找到证据”。
未找到不等于未做；没有来源不能编造统计。反复出现或单次代价很高的问题优先，
偶发低影响现象不要自动膨胀成通用 Skill。

若提出改规格、记 ADR 或补任务，附理由与影响，沿已有批准边界处理。
实现了修复不能倒推原需求本来如此；未授权的产品偏差保持未验收。
复盘不替代 Candidate Verify，不让 Thin Judge 探索代码，也不自动标记 Epic/Task done。
已有报告无法证明完成时明确缺口；真实产品收益与方法/接线通过分别报告。
