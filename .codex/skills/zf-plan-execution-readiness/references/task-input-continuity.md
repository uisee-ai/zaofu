# 任务输入与接力核查

来源：ZF-SPEC-001 F02/F03/F10/F17/F18，设计 207–209。
这是一种评审方法，不新增 task schema，也不改变当前 briefing 的批准与读取合同。

## 生产端先对账，再精简

为当前任务准备来源条款、验收责任、共享约束、依赖产物、验证条件的对照。
使用原有 task contract、task map 和输入选择字段，不复制第二份规范合同。
每条必要正文标明稳定出处和版本，未选正文保留查询入口及不适用理由。
重复别名可以只交付一次正文，但全部业务出处及访问权限分别保留；摘要不能代替必读正文。
输入修订不改变目标/AC 时说明保留哪些代码和证据；改变责任或验收必须走现有计划修订。

正例：支付任务选自己的验收条款、共享认证/幂等规则及订单依赖，不加载每个报表任务的细节。
反例：删除共享权限约束只为减少字节；保留整份全局 tasks 数组却声称已任务化；
把所有真实数据、性能、跨模块集成和部署资格交给无边界的最后一个任务。
Critic 指出具体遗漏的条款、消费者和可观察失败，不用体积阈值或 fixture 标签代替判断。

## 有限恢复与下一动作

以当前输入版本、attempt 和会话边界判断恢复范围。读取目录，再按受控游标补足必要正文；
已截断的页面补齐缺口，完整材料且条件未变时继续当前具体步骤。
`--resume` 的交付观察不证明模型记忆；材料已不在当前上下文时重新读取适用正文。
新会话不能沿用旧会话的记忆声明，历史读取不授权新执行者。
环境不可用、审批等待或外部效果未知时写明等待对象和核对动作，不反复重读整份计划。

## 拆分与接力的消费者

每个任务列出可独立验证的结果、依赖输入和最早反馈点；最后的集成任务有明确装配范围。
对只剩少量任务的前沿解释真实依赖、共享写资源及资格等待；不为填满 8 个 lane 造空任务。
分别核对 Impl/Verify 的就绪目标，容量足够不等于任务可执行。
交接标明目标与代码版本、已接纳成果、未接纳候选、未验证资格、已尝试失败和下一步；
用现有 work record / artifact / finding / checkpoint 受控入口落盘，不将聊天或原生 transcript
当成跨 Provider 的执行权，不复制凭据或内部推理。
保存材料、传输到接手者、接手确认和最终产品验收分开记录。
