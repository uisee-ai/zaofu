# 复杂切片与最早反馈

高复杂度片列出短小的实施步骤：每步的行为断言、有效 RED、实现、同断言 GREEN、
回归范围和返工责任。一个原子提交 owner 可以包含多个这样的步骤，不拆成多个
对外可见提交，也不另外派一个“以后补测试”的任务。
片内 RED/GREEN 命令只能依赖本片及已完成前置；最终 candidate 命令另列，不能因为
同一 AC 关联两阶段命令，就把后续候选命令复制进当前片的执行步骤。

UI 切片区分两类证据：本片已就绪行为的组件/真实入口 smoke，以及依赖未来片的
完整业务旅程。前者应在本片或最早可行阶段验证；后者保留 mandatory candidate
复验。明确为什么需要等待，不能默认把所有 UI 反馈排到 G2/G3 或最后一波。
任务数、AC 数和波次数不代表工作量；优先检查首次反馈距离、前置真实性、片内步骤
及故障重做范围。没有实际耗时证据时不宣称调度最优。
阶段 smoke 的排除范围不能直接复制给最终候选用例；Critic 逐项核对 candidate AC
承诺的业务旅程与标签/动作是否仍被用例排除，尤其检查从局部模板派生的最终用例。
