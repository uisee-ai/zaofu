# C-02 WRC frontier consumer 接线

> 状态: proposed

## 目标

把现有 Task Pipeline reconciler 正式接入 WRC consumer，保持 Kernel 的确定性 reconciliation、容量、lease、workspace 和 EventLog 所有权，不新增第二套 scheduler。

## 范围

- 新增小型 WRC frontier consumer facade，调用现有 `reconcile_task_pipeline_runtime`。
- 在 Orchestrator 的正常 dispatch 入口接线，记录 consumer 的 schema、owner、generation 与输入摘要。
- 派发 operation / stage event / worker envelope 带上 `frontier_owner`，便于审计和防止 owner 漂移。
- consumer 失败仍由既有 deterministic failure path 处理，不能让 legacy dispatcher 趁异常接管。

## 验收

1. blocking + owner=wrc -> verify: consumer 实际调用 reconciler 并产生 stage dispatch，事件 payload 标记 `frontier_owner=wrc`。
2. consumer 重放同一 EventLog -> verify: 不重复创建同一 operation/attempt。
3. consumer 异常 -> verify: managed fence 保持，产生 housekeeping failure，不生成 legacy dispatch。
4. 代码通过实际 `Orchestrator._dispatch_ready` caller 接线测试，不能只测试孤立模块。
