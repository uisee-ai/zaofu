# 局部计划变更的独立审查与准入

> 状态: active

## 问题与目标

身份和设计的局部 replan 触发全项目计划来源必读，阻断业务并放大输入。定义可审计变更范围及证据引用，保留既有任务图、原验收和独立 Critic；仅在完整范围、来源及下游影响可证实时允许局部审查进入现有计划准入，否则维持全量路径。

## 验收

- 针对明确受影响任务和下游的计划修订 -> verify: 审查入口获得原合同、新合同差异、相关依赖、原验收与来源索引，并可按需展开授权原文。
- 全局需求/合同变化、范围不完整、来源失效或验证责任无法证明 -> verify: 不使用局部准入，保留全量审查或明确阻塞。
- 局部审查通过 -> verify: 现有受控准入只更新经审查任务，保留其他任务状态、证据和最终验收，不把审查结果当业务 Verify。
- 失败恢复及重复派发 -> verify: 原始事件不可变、事务与权限无旁路，调用链回归及 mock E2E 通过。

## 实施进展（2026-11-02）

- 计划候选预检增加历史 Plan Package 的 Run 绑定检查，防止误用其他 Run 的基线。
- LS 当前重规划输入未声明受影响任务范围，不能仅从文件大小或人工摘要推断范围；局部审查产物、影响闭包证明及受控准入仍未完成，目前保留全量审查。
