# Critic 必读报告内部与独立工件重叠的上下文优化

> 状态: active

## 真实证据

隔离 PRD 真实 Codex 演练（Run `workflow-bd2c19fab1d1e446`）：Critic 输入策略
10 个必读来源均选 `$`，Planner child report 63,997 字节，内嵌 `plan_md` 与
独立必读 plan.md 15,345 字节逐字节相同；另含约 45 KB `plan_ports`，同批
还要求独立 task_map 等。`artifact read --required` 默认/上限 8192 字节（含
元数据），Critic 连续使用 cursor 消费 20 余页；operation 计量约 219 万 token
（其中约 200 万为跨调用累计缓存读取）超过 150 万上限而 blocked。
整段去重并不证明可移除嵌入字段或跨来源回执。

## 待验证与验收

1. 按操作身份、摘要及来源逐字段建立 report 内联内容到独立工件的覆盖证明，
   明确映射不到的 findings、约束、差异及拒绝路径 -> verify: 每个原始条款有
   可追溯覆盖，错误摘要/冲突/缺字段 fail closed，禁止凭文件名推断同义。
2. 设计经授权的来源级细粒度必读/引用复用及回执，保留完整未缩减工件按需
   检索和重放 -> verify: 原子来源、身份、摘要、权限和每条必读回执不丢失。
3. 用盲测、真实小/大 PRD、负样本比较语义发现率、分页和 token -> verify:
   独立审查无漏项且实际费用/请求次数改善；覆盖不完整时回退完整读取。
4. 跨计划版本差量交付、对话 session 保留和重启单独验证 -> verify: 无改变
   复用正确检查点；变更/损坏/缺会话安全回退，不凭摘要直接断言语义充分。
