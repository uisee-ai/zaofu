# 看板任务详情与任务对话

## 使用场景

操作者从已筛选的看板逐张检查任务。打开一张卡片，就能读懂要交付什么、现在谁在处理、遇到了什么问题。可以就地向 Agent 追问，查看依据，再返回原卡片继续检查。Multica 提供工作区导航、任务正文和属性栏的阅读布局；ZaoFu 依据已有的执行、交接与验收记录呈现任务进展。

## 页面与内容

桌面保留工作区导航，中间为可滚动的任务正文，右侧属性可收起。窄屏优先正文，通过「属性」查看执行进度、当前执行者、优先级和依赖。看板、列表、表格和任务直达地址使用同一详情。返回应保留视图、筛选、滚动位置和键盘焦点。

```text
工作区导航   返回看板 / 任务编号                     属性
             任务标题 · 来源                         执行进度
             任务说明与验收条件                       阶段结果、当前状态
             本轮交付与依据                           当前执行者（有绑定时）
             动态与执行现场（可展开）                 依赖 / 优先级
             ──────────────────────
             Kanban Agent · 最近一轮（有历史时）
             [询问或补充这项任务…]  [发送]
```

- 标题下按需展示任务来源、计划引用、实际进展。待执行任务直接进入说明。阻塞、返工或验证失败时突出原因、下一步和证据入口；完成时显示终态与可用的交付记录。
- 正文来自任务合同或交接目标。验收条件和验证结果独立呈现；只有存在对应证据时才能认定通过。交接分别展示派发与接收状态，完成交接只说明接手。
- 本轮交付复用成果引用、Git 改动、验证与评审投影。活动区展示本任务的业务事件。收到本任务的新交接、验收或裁决时，合并连续事件并重读更新的详情，保留正在编辑的内容。运行路线、并行分支、输入、工作目录、完整简报和诊断按需展开。移除 Summary、Activity、Evidence、Advanced 四个一级标签；任务内容仍可通过现有受控入口编辑。
- 输入框固定在正文栏底部，长任务的首屏即可提问。空对话仅显示 Kanban Agent、输入框和发送按钮，打开任务时保留阅读焦点。项目和任务共同界定会话与草稿；重新打开可读同一段历史。发送后原位展开回复，再次打开时显示最近一轮摘要，可展开历史、继续追问。任务修改提案在用户确认后交给受控动作。发送、权限、提案和执行复用 Kanban Agent 的受控通道。本地账号或 Controller 登录后，任务详情、看板和 Agent 统一使用当前浏览器会话的操作权限。只读会话可以查看历史。问答留在对话，状态变更通过任务动态呈现。
- 普通详情由系统自动分配和派发，显示当前流程阶段、已接纳的阶段结果和实际执行者。排队阶段隐藏执行者，尚未进入工作流的 backlog 显示「未进入流程」。明确要求人工证据时展示待补材料与运行处置入口。
- 数据缺失或读取失败时显示可解释的状态。普通任务无需占位的来源、依赖或并行记录。

## 验收

1. 从带筛选和滚动的列表或看板打开任务 → 标题、正文与右栏可读；浏览器后退或返回按钮恢复原视图。直接打开含任务参数的地址可阅读。
2. 查看阻塞或交接任务 → 首屏看到原因、接手状态及可用的下一步。展开证据可追到本任务的成果或当前执行的输入。
3. 同一项目的两张任务卡分别对话 → 请求绑定不同任务和线程，重开读取各自历史。普通打开仅进行读取，发送和业务操作沿用现有授权。命令面板的 Agent 入口聚焦当前任务对话框。
4. 窄屏查看详情 → 无页面级横向滚动，属性可开合，讨论、验收与返回均可用。
5. 阅读任务时收到验收或交接事件 → 详情和最近动态更新；未发送的对话草稿及未保存的任务编辑保留。
6. 使用账号密码登录后发送任务追问 → 受控动作凭会话 cookie 被接收，无须补填 action token；注销后原操作返回 401。桌面及手机均在顶部显示当前登录用户名，可打开账号菜单退出。旧 token 模式继续使用自己的授权入口。
7. 宽屏、平板和手机打开含长工作流或追踪编号的任务 → 状态和当前执行者在同一值列对齐，关联编号不挤占标签列，相同的验收描述只显示一次。
8. 打开长任务并滚动正文 → 三种宽度下输入框均留在首屏原位；发送后原位看答复，重开显示最近一轮。
9. 核对验证排队、执行、暂停和外部证据门槛 → 只有绑定中的运行实例显示执行者，人工证据入口只在对应门槛出现，普通编辑也不提供分配或派发。
