# 看板任务详情与任务对话

## 使用场景

操作者从看板、列表、表格或任务链接进入详情，阅读任务目标和验收条件，判断是否需要介入，然后就地追问或返回原卡片。桌面宽屏将工作区导航、任务正文与属性并排。标题、阻塞原因和任务对话在各屏幕宽度下都能直接阅读。

```text
工作区导航  │  ← 返回看板   TASK-TRAIN                    │  任务属性       ›
            │                                            │  优先级    P3
看板        │  训练参数注入与有效 checkpoint 恢复          │  来源      训练工作台
            │  执行受阻 · 需核对恢复后的训练参数           │  最近进展  进入阻塞
            │                                            │            35 分钟前
            │  恢复执行时应沿用该任务的训练配置和输入清单。 │
            │                                            │  关联任务
            │  验收条件                                  │  依赖任务
            │  • 恢复后的参数和报告可追溯到同一任务。      │  准备训练数据集 ↗
            │                                            │  TASK-DATASET · 已完成
            │  Task conversation                          │
            │  [问进展、补充背景，或提出任务调整…] [Send] │  查看任务事件 ↗
```

## 页面与数据

- 标题下一行显示当前执行状态。需要介入时，就地说明原因。当前流程明确受依赖阻塞时，提供尚未满足的依赖任务链接。人工证据门槛显示所需材料和处置入口。执行者显示在属性栏，仅使用当前执行绑定。
- 正文取自任务合同的目标或交接目标。验收段落有内容才显示，同一条要求展示一次。任务详情采用单一合同，验证命令和合同原文归入运行诊断。
- 有可访问的报告、文件或 PR 才显示交付结果。项目任务接口提供已接纳且有哈希核验记录的文本文件链接，打开时复核当前任务绑定、路径和内容摘要；浏览器还可打开验收依据中明确给出的 HTTP(S) 链接。
- 宽度达到 1200px 时，280px 的属性栏默认展开，收起偏好保存在当前浏览器中。窄屏通过顶部“属性”打开右侧抽屉，关闭后回到原任务。编辑任务使用独立的铅笔按钮。
- 属性栏展示优先级和已知来源。优先链接当前项目中可解析的父任务、来源任务或所属需求，同一来源显示一次。有当前执行者、子任务或并行进度时显示对应行，子任务列表可打开，已结束的并行分支与业务完成分开计数。
- 关联任务按依赖、下游两个方向展示标题、编号和当前状态。下游确有依赖门槛时加注“等待本任务”。已完成的依赖仍可查看，有其它原因的阻塞保留其实际状态。
- 最近进展取本任务最近一次有意义的状态变化或阶段事件，按时间显示距今多久。心跳、页面刷新及其它任务的提及均不会更新时间。属性栏底部的“查看任务事件”进入本任务的事件页，按需打开执行路线、输入、交接回执和运行诊断。
- 对话框固定在底部。项目和任务共同界定对话与草稿。默认展示最新回复，可展开历史。修改提案由用户在对话中确认，再通过现有受控动作提交。登录账号复用会话权限，只读和旧 token 模式沿用对应授权。

## Task conversation

任务页底部的对话区标题为「Task conversation」，发送按钮为「Send」。消息发给项目的 zaofu agent，自动引用当前任务。展开历史和收起后的最近回复均标明作者。右栏的「当前执行者」来自运行绑定，派发继续由 ZaoFu 自动完成。

| 用户意图 | 对话行为 | 用户可核对的结果 |
|---|---|---|
| 问进展，如“训练恢复为什么卡住了？” | 依据本任务的状态、事件或产物解释当前阶段和下一步。依据不足时具体说明缺什么。 | 回复署名 zaofu agent，引用相应记录。 |
| 补背景，如“断点文件来自旧版本” | 将信息留在本任务对话，供后续追问引用。 | 重新打开任务能读到原消息。写入任务要求需要明确的调整请求。 |
| 提调整，如“把旧版断点兼容加入验收条件” | 展示目标任务和拟更新的字段。追加验收条目时保留原条目和验证方式。 | 操作者点击「确认更新」，收到匹配的受控动作完成回执后显示「验收条件已更新」。请求仅被接收时显示等候回执，失败时显示原因。 |

对话回复表示 zaofu agent 已处理这条消息。只有能关联到本次交接和当前执行者的送达回执才能表示消息已送达执行者。运行交接详情可从任务事件页查看。

## 验收

1. 打开阻塞任务，核对原因只出现一次。没有成果时不显示交付区。运行事件和原始合同均由任务事件页按需打开。
2. 打开已绑定的交付文件，核对内容来自当前项目和任务。文件变更、绑定过时或不可访问时不返回原文。
3. 查看排队、运行、暂停、依赖和人工证据任务，核对状态和可执行的下一步。
4. 在桌面、平板及手机滚动长正文，核对输入框始终可见。连续追问并切换两张卡片，核对回复与草稿各属其任务。
5. 打开和关闭编辑菜单，核对编辑草稿在任务刷新后仍保留。返回看板时恢复视图、筛选、滚动和焦点。
6. 使用本地账号发送任务追问，桌面在左侧栏底部显示账号，手机打开导航后可从底部账号菜单退出，核对后续写请求返回 401。
7. 宽屏收起属性并刷新，核对偏好保留；在平板或手机打开抽屉，检查关联任务、Esc 关闭及键盘焦点。切回宽屏沿用桌面偏好。
8. 查看包含上下游、父任务或所属需求的任务，核对归属链接、状态及等待标记。连续心跳后仍显示最近一次真实阶段进展。打开关联任务后读取其自身的正文和对话。
9. 询问进展、补充背景并重新打开任务，核对消息和回复的署名。发起验收条件调整，核对确认前可见具体内容，操作完成、等待回执和失败分别给出相应反馈。
