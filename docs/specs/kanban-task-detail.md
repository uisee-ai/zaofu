# 看板任务详情与任务对话

## 使用场景

操作者从已筛选的看板逐张检查任务。打开一张卡片，就能读懂要交付什么、现在谁在处理、遇到了什么问题。可以就地向 Agent 追问，查看依据，再返回原卡片继续检查。Multica 提供工作区导航、任务正文和属性栏的阅读布局；ZaoFu 依据已有的执行、交接与验收记录呈现任务进展。

## 页面与内容

桌面保留工作区导航，中间为可滚动的任务正文，右侧属性可收起。窄屏优先正文，通过「属性」查看负责人、状态、阶段、优先级和依赖。看板、列表、表格和任务直达地址使用同一详情。返回应保留视图、筛选、滚动位置和键盘焦点。

```text
工作区导航   返回看板 / 任务编号                     属性
             任务标题 · 来源                         状态 / 阶段
             需要处理的事、下一步、交接状态           负责人 / 优先级
             任务说明、验收条件                       依赖 / 并行任务
             本轮交付、验证与评审、查看依据
             最近动态
             任务对话                 [发送]
             执行现场                 [展开]
```

- 标题下按需展示任务来源、计划引用、实际进展。待执行任务直接进入说明。阻塞、返工或验证失败时突出原因、下一步和证据入口；完成时显示终态与可用的交付记录。
- 正文来自任务合同或交接目标。验收条件和验证结果独立呈现；只有存在对应证据时才能认定通过。交接分别展示派发与接收状态，完成交接只说明接手。
- 本轮交付复用成果引用、Git 改动、验证与评审投影。活动区展示本任务的业务事件。收到本任务的新交接、验收或裁决时，合并连续事件并重读更新的详情，保留正在编辑的内容。运行路线、并行分支、输入、工作目录、完整简报和诊断按需展开。移除 Summary、Activity、Evidence、Advanced 四个一级标签；保留既有操作与授权入口。
- 正文下只有一个任务 Agent 输入框。项目和任务共同界定会话与草稿；重新打开可读同一段历史。长对话可展开再收起。发送、权限、提案和执行复用 Kanban Agent 的受控通道。问答留在对话，状态变更通过任务动态呈现。
- 数据缺失或读取失败时显示可解释的状态。普通任务无需占位的来源、依赖或并行记录。

## 验收

1. 从带筛选和滚动的列表或看板打开任务 → 标题、正文与右栏可读；浏览器后退或返回按钮恢复原视图。直接打开含任务参数的地址可阅读。
2. 查看阻塞或交接任务 → 首屏看到原因、接手状态及可用的下一步。展开证据可追到本任务的成果或当前执行的输入。
3. 同一项目的两张任务卡分别对话 → 请求绑定不同任务和线程，重开读取各自历史。普通打开仅进行读取，发送和业务操作沿用现有授权。命令面板的 Agent 入口聚焦当前任务对话框。
4. 窄屏查看详情 → 无页面级横向滚动，属性可开合，讨论、验收与返回均可用。
5. 阅读任务时收到验收或交接事件 → 详情和最近动态更新；未发送的对话草稿及未保存的任务编辑保留。
