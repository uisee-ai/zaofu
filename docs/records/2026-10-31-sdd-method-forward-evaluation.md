| B-S3 取消本人 | 有本人可取消预约 → 取消 → 从有效占用撤销；改为他人预约应拒绝不变。可取消时点、记录保留/状态、重复取消规则待定，不能擅定物理删除 |
| B-S4 管理统计 | 按产品确认窗口与口径查看/导出 → 结果符合决定并按期限保留。角色/指标/取消记录口径亦需设计确认；范围保留，尚非可派发空壳 Task |

超时显示结果未知并保留输入（B:5），不能声称保存失败。幂等/结果查询/安全重试尚待接口负责人确认；建议未知期间不自动重发，按确认后的核对途径恢复，不能假装已有查询接口。成功观察是正确浏览、预约唯一、失败无记录、本人取消与规定统计；无秒数/容量/KPI 基线，不增数值承诺。

候选任务修订（未修改或批准草案）：BOOT 保留已授权职责；READ 依赖实际 BOOT 入口，仅验读取；BOOK 消费 READ 的真实房间标识及已采纳合同，承担落库、登录/组织、并发、未知恢复；新增 **CANCEL** 补齐本人取消，依赖预约身份/状态合同；REPORT 保留后续必需范围，待统计口径确定后推导真实数据依赖，不能只按页面顺序加边。

最小用户链建议 BOOT → READ → BOOK → CANCEL，REPORT 暂作薄 Epic 留目标/决定/验收责任。此处不是完整合法 Task Map；未知未来范围不能铸为空壳 Task，也不能删掉统计以提交全 Goal。若要正式阶段计划，须有权者明确阶段 Goal 并保留总范围回访责任，本评估没有替其批准缩减。

关键验收：BOOK 用两个可独立成功成员、同房明确重叠样本（如10–11点/10:30–11:30，仅测试样本）在服务端屏障竞争，恰一个成功、失败方无记录；READ 列表全绿不能排除先查后写双成功。BOOK 另验未登录/跨组织无记录及提交前/后丢响应均按未知事实反馈；能力确认后才加适用的 key/query/replay 断言。CANCEL 验本人成功、他人拒绝及合同规定的竞争/重复；REPORT 待窗口/口径确认后验边界日期与有效/取消样本聚合及导出留存。

验证 owner 为各行为实际生产者对应独立 task_verify，最终跨片由 candidate_verify。项目 runner/命令/fixture/收据尚未确定，不编造已存在路径；相应正式 Task 形成前必须补齐精确命令与判定规则，BOOT 自身可按授权生产基础入口并提交前验证。

B 的分项结论：产品规格必须补取消；设计上 BOOT 可开展、READ 已定义范围可继续细化/实现，BOOK/CANCEL 不能假定未知恢复/接口就绪；来源覆盖须把并发验收从 READ 移交 BOOK；执行上保留健康入口/浏览的早反馈，尚不能认证全图调度或测试通过；治理上保留全部原始范围与待决定 owner，候选图仍待原有评审/批准。

## 实际检查、方法歧义与不能证明的结论

实际做了：完整读指定输入、按方法逐条来源/生产者/AC/阶段对账；审全部四个 WORK 场景并提出具体反例；解析 JSON、核对给定 ID 无重复、局部依赖/决定/命令引用、NOT_RUN 和路径前缀；生成第二领域规格与修订；保存摘要及 `input-checks.json`。没有运行产品/仓库/浏览器/数据库/真实 provider 测试，未核验 actual dispatch 的 Skill 物化。只写指定临时目录。
