**下一步顺序**

1. **先细化只读列表规划。** 引用已明确的需求与接口，列出验收对应关系。缺少正文时记录资料缺口，不把它变成新的产品决策。
2. **准备事务验证计划。** 硬约束保持为“库存和流水跨 Store-A、Store-B 同时成功或同时回滚”。现有 `put/get` 和单 Store transaction 说明都不足以证明满足该要求。
3. **获准后才开展隔离实验。** 保留来源的预算建议：最多 **20 分钟、2 个候选方案**，作为待确认的实验上限。候选方案须说明如何满足原要求；验证应覆盖正常成功、一侧失败、超时或中断后的两侧状态，并记录可复现证据。有限实验通过也不能单独证明全部原子性保证。
4. **根据证据解除依赖。** 若方案有充分支持，再细化写 API 和表单；若预算耗尽仍不确定，报告“未解决”，保持相关任务阻塞，只读列表继续独立推进。

- **实验授权及预算确认：** 由授权人决定，最迟在实验开始前完成；当前只准备计划。

- **事务方案决定：** 技术负责人提供证据和建议；若方案改变原子性要求，必须由产品负责人明确批准。当前没有降级授权，不默认接受最终一致性或补偿方案。
