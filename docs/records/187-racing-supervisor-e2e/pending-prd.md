## 用户、目标和范围

桌面 Chromium 用户打开单人 2D 俯视赛车，点击开始，以方向键或 WASD 自由驾驶，避开边界和障碍，在 90 秒有效时间内增加合法前进距离并减少碰撞。结果展示最终距离、碰撞次数及总分，可重新开局。
范围包括源码、配置、PRD/接口/实施计划、独立测试与真实浏览器证据。移动端触控、Firefox/Safari、联网多人、账号/排行榜、3D 明确不在本次范围。没有外部参考图或竞品被删去。

## PRD-01：驾驶与赛道（DEC-01 候选）

世界坐标以米计，x 向右、y 向下，朝向弧度以向右为零、顺时针为正。赛车碰撞体为半径 3m 的圆。
赛道是以 (300,300) 为中心、中心线半径180m的圆环，内边界140m、外边界220m；车中心合法范围为143..217m。
起点 (300,120)，车头朝右，顺时针为正向。8个等角检查点从起点每45度排列，必须按顺序前进。
障碍为半径8m的圆，中心 (480,300)、(300,480)、(120,300)。渲染和物理读取同一份 TrackDefinition。
赛道使用深色路面、明确内外边界、顺时针标识和高对比障碍，车体与路面可区分；Canvas完整容纳600×600m世界，保持比例，HTML HUD与按钮不遮挡赛道。
目标视口为1280×800与1440×900，均须能看见全部核心操作与结果，不新增移动适配承诺。

ArrowUp/W 加速，ArrowDown/S 刹车，ArrowLeft/A 左转，ArrowRight/D 右转。
加速度8m/s²、松油门阻力2m/s²、制动18m/s²、速度范围0..45m/s；刹车优先于同时按下的油门，左右同时按下等于不转。
朝向以160度/秒连续改变，静止时也可改变方向但不会得距离；不使用固定车道切换。刹停不倒车；用户可转向180度朝反方向驾驶。
运动采用小步半隐式更新：先更新速度与朝向，再以该速度/朝向提出位移；每物理步≤1/120秒，最后不足一步按实际余量。
键盘只在游戏容器激活时阻止方向键滚动；keyup、失焦、暂停、继续、重开都清除输入锁存。控制说明始终可读。

## PRD-02：接触与合法距离（DEC-02 候选）

运动必须检查整段路径的首次碰撞而非只检查终点。接触内外边界或障碍时，停在首接触前可行位置，速度归零，不能穿透。
接触状态记录当前稳定 collider ids；一次连续接触 episode 从无接触到有接触只发一次事件，同一物理步碰到多个物体合为一次并排序记录ids。
持续贴墙或障碍不逐帧扣分；和所有接触物体分离超过0.01m后再次碰撞才开始下一事件。移动方向离开表面可解除接触，不能永久锁死。
每个新碰撞事件立即增加计数并给车体/边框300ms红色闪烁及“碰撞 -20”文本；仅视觉反馈计时可继续，paused时比赛状态冻结。

沿赛道中心线角度展开计算有符号路线进度，检查点有序且每步检查扫掠路径；完整顺序一圈增加2π×180m。
保留历史最高合法进度 highWater，新增有效距离为 max(0, newProgress-highWater)，再更新 highWater。
逆向行驶降低当前位置进度但不减已得距离；逆向后回到旧最高点不重复计分；跨起点的圈数只在顺序检查点确认后增加。
静止、原地转向、横向抖动、逆向折返、越界切内圈、跳过检查点及超过速度×dt上界的跳变均不能增加有效距离。
碰撞前真实走过的合法路段可计分；恢复/位置纠正本身不得计分。碰撞和进度由同一次已提交运动原子计算，不读取渲染坐标。
分数 = max(0, floor(有效距离米数) - 20×碰撞次数)。例如125.9m、2次碰撞=85分；0m、1次碰撞=0分。
内部保留距离小数，HUD与结果均显示一位小数；分数整数只由统一函数派生。

## PRD-03：状态、时间与结束（DEC-03 候选）

状态枚举 ready / running / paused / finished。ready 显示说明、90秒倒计时与开始按钮；其余按钮按状态显示或禁用。
start 仅在ready有效，原子重置并进入running。pause仅running有效，进入paused；resume仅paused有效，重新建立单调时钟基线后进入running。
restart在running/paused/finished有效：重置车姿态、速度、输入、计时、距离、进度highWater、检查点、碰撞数与接触集、结果及结算计数，然后直接进入新一局running。
不适用状态下重复start/pause/resume为无操作。finished只能通过restart开始新比赛。
失焦/visibility hidden自动暂停，回到页面仍paused，必须按继续按钮；单测可以注入时钟，正式比赛禁止测试时钟或时间缩放。
计时以单调时钟累计running间隔，且只累计到90000ms。正常前台比赛真实运行90秒。物理分步不能丢弃正常间隔来延长比赛。
长间隔由多个≤1/120秒子步处理；若跨90秒只模拟剩余有效时长。不能通过简单clamp dt丢弃有效时间。
每一步顺序为：规范化输入→时间上界裁剪→提出运动→碰撞裁剪/接触事件→合法进度→统一得分→时间更新→若到90000ms只结算一次。
最后有效步中的碰撞/进度应计入终局；90000ms之后任何事件不再进入本局。
paused时车姿态、时间、距离、计数、分数、进度和接触集完全不变；resume不补算暂停间隔。
finished生成不可变RaceResult，事件race.finished仅一次；继续rAF或按键不能改变结果。结果屏必须展示最终距离、碰撞次数与总分，结束面板的重开按钮文案统一为“重新比赛”；行为仍遵循本版既定的重开规则。

## PRD-04：可观察性与验收

正式页面为 /；片内演示只是早期反馈，不能代替正式游戏。
HUD以可读DOM显示剩余时间、距离、碰撞数、分数和状态；Canvas与HUD都消费同一只读快照。
测试观察接口只能读取快照，不提供改状态、调时钟、传入短赛程或自动结束的方法；浏览器测试动作必须来自真实键盘/页面按钮。
每个浏览器用例记录console.error和pageerror并断言为空；截图和像素前后差异只作动态画面证据，必须结合DOM/位置/朝向/得分业务断言。
完整90秒用例必须独立于暂停/重开用例，不能因提前重开中止唯一完整比赛。允许键盘自动化正常驾驶，禁止直接注入位姿。
测试记录开始/结束performance.now及有效时间；正常比赛有效时间恰为90000ms，真实单调时长不少于90000ms，测试超时180秒，结束后2秒快照稳定。
静止/无效移动防刷、同接触去重、分离再撞、真实按键双映射、暂停2秒、继续、重置及终局稳定均有独立场景。

## PRD-05：交付与治理

编排侧提供恰好3实现lane、至少2独立验证lane（当前编译为3）、独立Judge与Kernel交付。
当前有效策略要求Plan审批；建单、Workflow启动和Plan批准分开。当前Planner只生成可审阅产物，禁止游戏实施、产品Verify或自批。
Plan获批后交付根入口 bash scripts/verify-racing.sh。全部阶段完成成功才返回0；安装失败、任何测试失败、必需用例跳过、证据缺失和超时均非0。
浏览器必须在Docker mcp/playwright:latest、--network host内运行，宿主禁止安装/下载浏览器。服务绑定0.0.0.0，端口从8004起选择可用值；绝不使用8001/8002。
每个执行者重新preflight自己的Docker权限、镜像digest、UID/GID写权限、host网络、端口和容器fetch。不能把环境失败改成测试通过。
每次验证原子创建独立run目录；原始stdout/stderr逐字节保存，空白/CRLF不清理；另写摘要和sha256清单。重跑只新增目录，不覆盖或删除历史。
.gitignore只忽略指定依赖/构建/缓存输出，不忽略源码/测试/脚本/文档；不放宽clean/diff门禁。
预算未配置/零限制不代表无限或充足；由监工观察实际成本、超时和provider失败，必要时受控修订，不降低90秒要求。
