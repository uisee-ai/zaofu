## 5. 方案 A：输入减负与成本测量

### A1. 建立能区分成本来源的观测

复用现有事件、调用账本和 read ledger，在非权威报告中按候选/角色/attempt 汇总：

- 排队、启动、执行及阶段间等待；不能从总耗时倒推出模型推理时间。
- 必读去重字节、实际返回选中内容字节、重复返回字节、分页数、截断补读数、展开次数。
- 非缓存输入、缓存读取、输出 token；供应商不提供的项记 unknown，未定价不记作免费。
- finding 的确认/误报/未证实、返工轮数、影响范围是否扩大、原始需求覆盖与最终产品结果。
- 增量资格：符合条件、实际使用、正常全量、资格不足回退；分别列分母，不追求所有修改都增量。

同一内容跨路径返回不能因文件名不同漏算重复；不同版本不能因名字相同误算缓存命中。按现有摘要和选择身份计量，不把分页重复声明的总大小累计为实际读取量。

### A2. 一个事实保留一个主要正文

原始需求不压缩替换；任务保存完整本片行为，共享义务由现有共享正文承载，矩阵主要描述映射。六类既有报告 ref 路径继续复用，不再同时输出完整 inline body 和相同文件正文。

阅读页可按引用组合展示。任务拿到的是本片及相关共享内容，不能只给索引让 worker 猜测。现有消费方仍要求的字段或完整端口必须保留，修改合同需先补齐调用者和回归。

### A3. 按职责选择内容，保留展开

| 角色 | 默认必须包含的语义内容 | 避免重复承担的工作 |
| --- | --- | --- |
| Planner | 原始来源、已确认约束、相关项目事实、修订反馈 | 反复探测已给定配置与未来审批是否完成 |
| Critic | 原始约束、候选行为、验收责任、完整相关决定、变化与受影响消费者 | 阅读同一义务的多份完整副本 |
| Task Verify | 本片 AC、前置已交付能力、相关共享规则、当前目标和探针 | 执行未来尚未生产的入口、替后继完成验收 |
| Candidate Verify | 最终候选、跨任务行为、产品验收和必要回归 | 将作者自报或本片局部通过替代集成检查 |
| Discovery | 原始目标、覆盖关系、已接纳验收及未解决问题 | 无新风险或缺口依据地重复生成相同验收证据 |
| Judge | 强制目标、支持与反对证据、例外决定、当前身份和开放缺口 | 重新运行产品测试或恢复整个实施探索过程 |

输入必须保留错误、未审项、适用条件、反证、waiver 和尚未闭合的义务；不能用“passed”汇总取代行为判据及支持关系。底层原文完整保存，可经受控读取展开；证据不足时 blocked 或扩大审查，不默认通过。

本项涉及 required-read 策略时必须修改相应运行时合同和测试，不能仅在 Skill 中要求“少读一点”而与实际强制输入冲突。

## 6. 方案 B：增量修订与 finding 收敛

### B1. 区分四种审查情形

| 情形 | 审查方式 | 复用限制 |
| --- | --- | --- |
| 首次候选 | 完整语义审查 | 无历史通过可继承 |
| 审批前被驳回后的修订 | 未关闭问题＋变化正文＋依赖影响范围；保留原始约束检查 | 只复用已绑定审查事实；旧 rejected 结果不能变成批准基线 |
| 已通过 Plan 的局部修订 | 优先走既有 scoped review | 必须满足已通过基线、来源、范围及历史证据条件 |
| 全局/共享变化或范围不明 | 扩大到全部受影响消费者，必要时全量 | 不因作者标注 local 或声称未变就缩减审查 |

审批前的增量不是放宽 `verdict == passed` 条件。应在现有评审/修订工件机制上设计可核验的审查覆盖记录，明确哪些问题仍开放、哪些原句和关联曾被审查，以及在新版本是否仍适用；其完整合同需在 B1 实施前提交细化评审。

### B2. 版本绑定与语义影响的分工

Planner 在现有修订材料中说明：旧新候选身份、变化位置、理由、受影响任务/共享规则/消费者、未变义务，以及旧证据继续适用或失效的依据。控制侧已有的引用、摘要和分区元数据由工具提供，避免 Agent 手工抄写大量身份字段。

独立 Critic 验证影响范围并可扩大读取。必须保留依赖闭包中的前置、下游、共享路径和最终验收责任；修改任务集合、需求范围、审批决定或环境假设时重新评估全局影响。

Runtime 负责检查候选身份、digest、来源权限、记录完整性和受控范围，不能从关键词或字数判断业务影响。历史阅读收据仅证明内容交付，不能独立证明理解、正确性或当前记忆。

审查策略/方法版本变化、需求或环境假设变化、相关证据过期、目标提交变化均需要重新判断适用性。来源缺失、分区不完整或恢复绑定无法证明时，扩大至完整输入或按现有路径 blocked，禁止静默降级为通过。

### B3. 先验证阻塞问题，再触发返工

复用既有 findings/review，每条问题保留稳定身份、候选身份、来源原句、冲突位置、最小反例、受影响消费者和关闭条件。作者修复记录与独立关闭判断分开。

- 可以机械核验的 JSON 解码、路径存在、摘要、受控语法检查交给现有工具；不增加针对业务措辞的硬编码 gate。
- 真实产品失败、规格矛盾、缺少证据、尚未核实疑问分别表达，疑问不伪装成已确认缺陷。
- 只修改展示格式或换一种措辞，不自动算问题关闭；若确认原 finding 错误，保留撤回依据，不要求虚构修复。
- 对高影响或有争议的 finding，允许提出有边界的独立复核；不默认给每个问题增加投票 Agent。
- 若同一问题在内容未变时反复出现，报告未收敛原因并沿已有恢复/人工路径处置；不通过增加轮数掩盖循环，也不为节省预算自动批准。

## 7. 方案 C：交付后复核与审查强度

### C1. 让 Thin Judge 的输入真正收敛

在现有 Goal Claim Set、已接纳结果、closure fact 和 target snapshot 之上，选择完整的“条款—支持结果—限制/反证—开放问题”内容，并绑定原文选择摘要。优先复用既有选择机制；不得新增与 canonical state 争夺权威的事实库。

Judge 仍要独立判断证据是否足以关闭每个 mandatory claim。输入不能由 Planner 自报闭合，不能丢弃失败探针或把不同 target 的结果拼成通过。原文展开及其成本计入测量；如果频繁展开，先修正输入充分性，不以禁止展开制造提速。

### C2. 风险与模型分级单独试验

先固定模型/推理强度取得 A/B 的收益，再对局部低歧义修订与共享/权限/数据迁移等高影响修改进行分组对照。风险适用性由 Agent 判断并留证据；允许的配置、预算、路线和升级方式仍由 `zf.yaml` 控制。

不能按文件少、AC 少或作者说“简单”直接减弱审查。语义不确定、反例不足、跨任务影响较大时扩大审查。超预算应走既有中断/恢复路径，不能把截止时间当作通过判据。

本方案不预先批准更换模型、取消阶段、增加常驻 Agent 或并行化有依赖的阶段。共享同一冻结候选的独立工作是否可并行，需要在职责和证据依赖已经证明后另行决定。

| B-01 审批前修订 | 既有 review/rework 工件、输入选择、恢复调用者 | 先细化 rejected 审查事实合同，再接入真实修订入口 → verify: 复用不等于批准，开放问题保留，错误基线及恢复错配拒绝 |
| B-02 已批准增量 | 既有 scoped review 与 Planner 生成接线 | 合格修订产生并消费范围材料 → verify: 正常增量、缺证据回退、共享变化扩展、旧证据失效均可复现 |
| B-03 问题收敛 | 现有 Critic/修订方法及正反校准 | 核实 finding 并按身份关闭 → verify: 转义误报撤回，真实冲突不被格式修改关闭，正确样本不制造返工 |
| C-01 Judge 输入 | goal_closure_bridge、已有选择和 Judge 方法 | 提供充分的条款证据选择 → verify: 全部 mandatory claim 保留，反证不隐藏，过期/混合目标拒绝，展开可追溯 |
| C-02 分级对照 | zf.yaml 配置提案与固定评测 | 单独改变审查强度/模型 → verify: 分风险报告质量和总成本，保留升级/回退，未经批准不改生产配置 |

A/B 不承诺消除所有性能问题。各包只在真实入口接线并取得对应证据后完成；函数测试、模板存在或短文本通过均不足以代表真实工作流收益。

## 9. 验证方案与试验目标

### 9.1 分层取得证据

1. **机械回归**：引用摘要、分区选择、失效、权限、缺失原文、错误基线、恢复重放、读收据与结果准入。跨 Event/Store/配置/恢复边界时按仓库要求执行影响闭包、pre-merge sentinel 和相关 mock E2E。
2. **固定工件回放**：使用同一旧新候选与 finding，不重新生成输入；每组方案至少 3 次真实模型 trial，固定模型/推理强度与工具版本，顺序交错并记录缓存条件。小样本只能作为试点信号。
3. **真实双入口**：当前未优化版本与候选版本各跑 Kanban/Channel；固定原始需求及修订脚本，至少覆盖 CLI 与另一个共享状态/接口场景。自然返工次数也作为结果，不能删掉失败轮次。
4. **独立质量复核**：模型校准与人工抽审分列；真人理解时间若未测继续记未测。只在已授权测试批次内运行真实 Provider，保持隔离状态，临时端口使用 8002+。

先做可控回放再安排完整真实运行，避免每次方法小改动都重跑小时级交付。真实双入口仍是最终效果证据，不能由回放替代。

### 9.2 必须包含的样本

| 类型 | 应有行为 |
| --- | --- |
| 正确不变候选、纯格式修订 | 不制造语义缺陷；机械绑定仍有效 |
| 单任务局部 AC 修订 | 识别变化及其直接消费者，不无故重开无关任务 |
| 共享规则修改、间接依赖 | 扩大范围并重审受影响证据，不只看 changed file |
| 任务增删、优先级或 mandatory 改动 | 对账原始授权；必要时全量审查 |
| 被驳回候选修复一个问题 | 未修复问题仍开放，旧 rejected 结果不变成通过 |
| 空决定登记、首片混入最终验收 | 保留上轮发现能力，不能因压缩而漏掉 |
| JSON 包装转义与实际命令错误 | 前者不误报，后者必须有实际字段或安全探针依据 |
| 过期/不同目标证据、缺文件、方法版本变化 | 失效、展开或 blocked；不能静默复用 |
| 隐藏反证、摘要声称通过但原文失败 | Judge/评审应识别不充分证据 |
| 同代重试、重启恢复、重复提交 | 不继承错误读收据、不重复状态转换、不绕过授权 |

### 9.3 质量约束与性能目标

以下为建议的试验验收线，不是已实现收益，也不是统计学上的生产保证。

| 指标 | 初期目标 / 判定方式 |
| --- | --- |
| 固定回归集质量 | 不新增已标注严重缺陷漏检，不新增把正确样本改坏的阻塞性误报；结果按样本列出 |
| mandatory 与证据绑定 | 无遗漏、越权或混合版本；产物行为由独立 oracle/真实验收证明 |
| 局部修订 Critic 时延 | 配对回放的中位执行耗时至少下降 30%；同时报告全部样本和尾部，不与历史五轮总和直接相比 |
| 重复正文返回 | 同一 attempt 内重复选中正文 bytes 至少下降 50%；与必要唯一字节分列 |
| 增量路径有效性 | 标注为合格的案例实际走增量；不合格样本正确回退，不要求全局增量率达到任意比例 |
| 返工成本 | 记录每个确认问题的生成、复核和修复轮数，单列误报引发的额外时间 |
| Judge / Discovery | 在充分性不退化前提下报告各自输入、展开及耗时；先建立当前基线，不预设任意绝对分钟上限 |
| 总交付成本 | 端到端耗时、输入/缓存/输出 token、失败和人工介入共同报告；不能只优化 Critic 而把成本转移到 Planner |

若速度达标但质量不达标，该方案不通过。若质量达标但速度未达标，标为收益未证实，依据分项数据调整；不通过降低测试要求兑现提速目标。

## 10. 迁移、回退和非目标

- 旧候选和历史工件保持不可变。新的消费策略通过现有受控入口接入；未知版本、缺少证明时沿用完整审查，不能覆盖历史 verdict。
- 首先在隔离试点比较输入选择与实际结果；生产启用策略、模型/预算调整单独由 Owner 确认并通过配置生效。
- 新策略发生质量回归时恢复旧的完整输入策略，保留失败证据；回退不删除事件、不伪造批准、不直接修改 canonical Store。
- 不新增第二套 Task/Goal truth，不把必需 sidecar 降为可丢弃缓存；非权威成本报告可再生成。
- 不以摘要、token 缓存命中、历史通过、模板字数或评审总分代替当前语义判断。
- 不在本轮删除交付门禁、引入普遍多 Agent 投票、改真实开发端口 8001、merge 或 push。

## 11. Review 后的落地顺序

Owner 确认本文范围后，再将选中的工作包转成 backlog，明确每包的调用者、保护边界、验证命令和预算。推荐先批准 A-01～A-03、B-01～B-03 的实施范围；其中 B-01 先完成合同细化评审，C-01/C-02 保持后续候选。

每批汇报必须分别给出：已落地代码、真实生效证据、质量变化、成本变化、尚未覆盖的场景。目标是减少不必要工作并提高有效发现率，不能用“实现了增量函数”或“总字数减少”宣称整条工作流已经变轻。


## 12. A/B 实施细化与边界（2026-11-13）

### 审批前 rejected 事实合同

复用现有 `plan-synthesis-result.v1`，不另建 Task/审批 schema。受控 rework 触发的
`rework_of` 必须通过同 Run 的 kernel 因果链定位唯一 Critic；验证其原始 request、
候选合同、独立生产者、admitted envelope、sealed read ledger 和 Provider 输出观察。
完整原 control result 以 `plan-rejected-review` 加入当前 immutable manifest，作为
必读事实交接；保留全部 findings、未审项、结论和证据引用，作者无权替换为已关闭摘要。

本次实现采用保守的事实复用层：**当前候选、原始约束及已有强制输入仍完整审查**。
旧 rejected 仅说明当时观察到什么，不能证明未列问题的部分已通过；目前没有逐义务
语义覆盖证明，因此不据此免读当前未变正文。这是 B1 的明确回退边界，不能报告为
“审批前已实现变化正文专审”或宣称其性能目标已达成。后续若缩减当前正文，必须
补齐覆盖证明及其失效/恢复合同，保持独立 Critic 和本版 verdict。

任何身份、读证据、权限、摘要或因果链缺失时不复用该事实源，仍走现有完整 rework
输入。既有 passed Package 的 `_previous_critic_manifest` 仍要求通过结果；公共
身份验证只被复用于事实核验，不将 rejected 作为它的批准基线。重放同一个 trigger
固定同一 control result ref/digest；新触发重新验证，不从“最新评审”猜测身份。

### 确定性改动和语义所有权

- `prepare_fanout_synth_reports` 在引用已复制到 runtime 后，仅移除六类端口中与
  引用文件解码内容完全相同的 inline 副本（包括实际生成的 `plan_ports[].body`）；
  对已有显式 ref/digest 的其他端口也只做解码后内容完全相同的引用转换。
  六类端口若仅有 inline 正文，则先用既有 immutable Plan port writer 完整持久化，再交接
  ref/digest，避免下游提取正文后与 child report 重复。已有引用缺失或冲突时不替换。冲突、摘要不符
  和不可读引用保留。原 admitted
  producer result 不变，Critic、预检和 Package 继续消费完整引用正文。
- canonical required reads 合并同摘要、选择、权限、保留策略、来源事件 的正文
  别名，所有 source 身份及受控展开仍在 manifest 中；explicit required reads 不减免。
- `zf plan prepare-scope-review` 从最终文件计算既有证书摘要，检查任务集合、共享
  正文、无关任务及依赖闭包。布尔语义声明、原始约束引用及受影响 ID 必须由 Agent
  提供。命令成功不是增量资格；dispatch 的历史通过、权限和实际读取证明仍是必需条件。
- `zf artifact costs` 与 Web 同源报告增加分页/partial 返回、attempt 墙钟时间和
  精确绑定派发事件的评审策略。queue/execution 是事件观察，不等于 provider 启动或模型思考。
  缺少阶段边界、供应商工具数、截断修复归因的项为 null；不得以零参与节约计算。
- findings 的确认、撤回、关闭仍由独立评审方法负责。复用已有记录，不引入按措辞
  自动判断缺陷的 runtime gate；精确 JSON 解码、正例和真实冲突作为校准样本。

### 验证归类

工程合同、固定模型回放、真实 Kanban/Channel 交付、成本收益四类结论分别记录在
本批任务和 `reports/spec207-optimization/`。单次真实成功不等于稳定收益；同机并发
的墙钟时间不作因果性能结论。C1/C2 保留 deferred，未更换生产模型或关闭评审阶段。


固定真实输入：[CLI 共享只读规则](../../tests/fixtures/spec_handoff_eval/shared-readme-product.md)
与[共享保存状态／正式接口](../../tests/fixtures/spec_handoff_eval/shared-save-product.md)。
前者验证到审批后交付，后者验证到完整 Plan Preview；后者的产品实现与运行验收不冒充已测。


真实来源补验发现：Codex session ID 可以在 operation started 之后才产生。历史复用
允许从已接纳 envelope 绑定的 sealed ledger 中恢复唯一 session，至少一条 receipt
必须精确匹配 operation/attempt/Run/actor；缺身份的历史分页不能单独建立此证明。
仍要求实际 provider transcript 观察、完整原始 request/policy/candidate 绑定和独立角色。
多个 session、其他 operation、缺启动事件或摘要不符仍回退；旧 passed 判定条件不变。

UI 真实测试保持默认单轮等待 600 秒；`--turn-timeout` 可显式设置不超过总预算的
补测等待时长，写入 run.json。延长等待的补测与原超时样本分开，不能宣称生产延迟已修复。

成本视图读取 kernel 派发事件中绑定 operation/request/attempt/manifest 的评审策略；
评审结果用 envelope 与 admission 的 ref/sha256/schema 身份匹配，附加审计元数据不要求相等。
冲突或证据缺失仍显示未知，不把 reviewer 声明当作独立质量真值。

引用优先必须贯穿最终 fanout 聚合：capability/acceptance/test/real_e2e 的 scalar ref
与已有 source_inventory/source_index 一样进入聚合 payload 及 artifact/evidence refs。
只有直接 port materialization 通过不够，还须验证聚合后的 blocking Package 准备入口。

显式端口 ref 优先于同名工件发现；其缺失、冲突或摘要错误时保留原正文与引用，
不改选另一个同名 ref 来掩盖错误。评审方法同时核对证据生产者的实际派发写权限，
只读 Verify 经受控结果端口交付，不因 Task 的 allowed_paths 推断验证者有产品写权；
缺少配置事实时报告未知，不编造“未配置 Critic”等阶段结论。
