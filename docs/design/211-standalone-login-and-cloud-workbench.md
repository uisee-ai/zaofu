# 211. Standalone 账号登录与云端个人工作台体验

用户打开新安装的 standalone，使用初始用户名 `zaofu`、密码 `zaofu` 登录，即可操作工作台。云端用户使用自己在 Controller 注册的 Keycloak 账号，获准使用空间后从控制台或工作台地址进入自己的实例。两条路径使用风格一致的登录页，进入同一套 ZaoFu Dashboard。用户发起 Kanban Agent 操作或输入终端命令时，无需再找 Action Token。

**状态**　已在独立工作分支实施。本文细化设计 203、204、210 的浏览器入口。实现与验收记录见[实施任务](../../tasks/done/2026-11-19-0202-standalone-login.md)。

## 1. 用户从哪里登录

| 入口 | 用户凭据 | 登录后的行为 |
| --- | --- | --- |
| Standalone | 本地单用户账号，初始为 `zaofu / zaofu` | 首次登录直接可用。用户可在工作台主动改密，也可以一直保留默认密码。离线可登录。 |
| 已注册上报的 standalone（`observed`） | 同一份本地账号 | 注册前后沿用同一密码和工作台。Connector 用节点机器身份向 Controller 上报。Controller 暂时离线时，本地仍可使用。 |
| 云端 Controller | 用户在 Keycloak 注册的个人账号，可按 realm 配置使用邮箱或用户名登录 | 用户提交空间申请，管理员以自己的身份审批。能登录控制台的用户仍可能处于待审批状态。 |
| 云端个人工作台 | 同一个 Keycloak 用户，工作台通过 Gateway 建立自己的会话 | 已登录 Controller 且 SSO 会话有效时直接进入获准的个人实例。直接访问工作台且未登录时跳转到 Keycloak，完成认证后回到原入口。 |

**安装体验。** 保留安装器现有的 standalone、注册上报、使用云空间和卸载选项。安装本地节点后输出普通 Dashboard 地址，以及初始用户名和改密入口的说明。安装器默认监听 `127.0.0.1`，需要对外监听时沿用 `--host`。局域网或反向代理均使用相同的登录流程，安装时无需选择网络场景，也不以改密作为开启远程访问的条件。对外开放且保留默认密码时，任何能访问入口并知道默认密码的人都能操作终端。在安装说明中说清这一点即可。

**云端身份归属。** Controller 和工作台各用自己的 OIDC 客户端和站点 Cookie，单点登录来自 Keycloak。Gateway 按当前用户、空间归属、准入状态及运行策略授权。注册、审批、实例就绪是三个独立状态。密码和密码哈希只由身份提供方管理，Pod 接收已验证的请求身份。云端停用或撤销空间授权后，已有工作台会话也受撤销约束。对于外部节点，只有显式完成 `managed` 接管才切换到受管认证。断连、租约失效或绑定错误都不能启用本地密码入口。

## 2. 登录前后的界面与权限

- **本地登录页。** 登录表单采用 Gr8r 的上部品牌栏、居中纵向表单、左对齐字段和整行主按钮，左上角仅显示 ZaoFu 字标。Geist 字体随安装包离线提供，中文字形沿用设备的无衬线字体。表单最大宽度 380 px，标题 23 px，输入框与主按钮均高 36 px。登录后，侧栏底部显示当前本地用户名；其菜单提供密码设置与退出。
- **进入工作台。** 本地和云端个人实例使用同版本官方 Dashboard。项目、Session、Kanban Agent、Web Terminal 的导航及操作位置一致。Controller 自己的实例清单、审批、用量统计仍在控制台。工作区尚无项目时，打开 Kanban Agent 或 Web Terminal 会进入添加项目窗口；选中的项目尚未初始化时，会进入项目初始化页面。具备本地账号会话或云端可写授权时，欢迎向导、项目接入弹窗和 Agent 菜单均不再要求输入 Token。
- **可写权限。** 本地登录获得原本地 Action Token 能授权的 Web 操作，包括已有受控写操作。动作仍经过原有内核入口和项目检查。Kanban Agent 沿用默认 `workspace_writer`，Web Terminal 默认以 `control` 连接，已有占用仍遵循现行接管流程。显式启动为 `--read-only` 或受云端策略限制时，服务端继续按实际权限处理，登录成功本身不能提升权限。
- **退出与改密。** 工作台提供退出入口。本地改密位于 Settings → Security → Password，空工作区也可访问。表单要求当前密码、新密码并确认新密码。修改成功后使用新密码重新登录。刷新、进程重启、升级及重复运行安装器均保留已设置的密码。云端用户通过 Keycloak 管理自己的密码。

### 2.1 首次进入实例的欢迎向导

本地和云端个人工作台共用现有首次设置向导。每个安装或云空间单独记录进度。新浏览器、新的登录会话及注册成为观测节点都沿用已有进度。

| 使用场景 | 用户看到的顺序 |
| --- | --- |
| 新装 standalone（含仅上报节点） | 本地账号登录 → 首次设置 → 工作台。向导可跳过，用户可在空工作台自行添加或初始化项目。 |
| 新建云空间 | Keycloak 登录 → 申请获批、实例就绪 → 进入自己的工作台 → 首次设置。Provider 和环境检测针对该实例。已由平台配置的模型接入沿用实例配置。 |
| 回访、恢复与只读访问 | 已完成或已跳过的实例在登录后直接进入原页面。中途退出的可写会话在下次登录后续接。只读会话进入只读工作台，不显示可写向导，也不写入跳过标记。 |

保留现有 **Provider → Environment → Access → Ready** 四个持久化步骤编号。建议账号登录和云端 SSO 用户在环境检查后直接看到 Ready，由页面显示当前会话的授权状态。跳过 Access 的交互页即可，无需改写旧进度文件。恢复到旧第 3 步时，按当前会话重新判断权限。仍使用旧 Token 方式的安装继续沿用原 Access 步骤。完成或跳过向导只保存实例设置，项目创建由用户单独发起。Provider CLI 自身需要的账号或 API 凭据仍依模型接入方式配置。

页面先确认会话和实例，再读取 `/api/workspace/onboarding`。当前 Dashboard 挂载时并发读取会话及向导，读取向导失败会隐藏它。在新流程中，先等登录成功再读取，401 回到登录，临时加载失败提供重试。保存步骤、跳过和完成均须通过服务端写权限检查。会话中途失效时保留上次成功保存的步骤，重新认证后续接。向导进度继续使用实例 workspace home 的 `onboarding.json`，云端位于该空间的持久卷上。

## 3. 实施合同

以下为工程建议，供本次评审裁定。尤其需要确认第 3 项的旧安装迁移策略。

1. **凭据归属。** 每个本地安装的 workspace home 管理一个账号，多个项目共用。沿用现有 workspace home 解析和文件锁，原子建立受限权限的加盐密码哈希。并发启动只初始化一次。已有凭据损坏时给出本机恢复指引，避免重新启用默认密码。恢复由具有该安装目录权限的本机操作者执行。机器上报凭据、模型服务密钥及项目运行状态分别保管。
2. **浏览器会话。** 在现有 Web 会话入口补齐登录、状态、退出、改密，复用现有鉴权与受控动作。账号模式下，匿名访问页面进入登录页。直接访问业务读取、写入、事件流或终端接口须验证身份。业务 API 未登录返回 401，已登录但权限不足返回 403。登录页资源、最小会话状态和不含项目数据的健康探针可匿名访问。静态回退页面和项目深链接也遵循同一边界。浏览器会话采用有期限的 HttpOnly、同站 Cookie，HTTPS 入口设置 Secure。服务端保护登录及后续写操作的来源与 CSRF 边界，保留登录失败限速。退出撤销当前会话，改密撤销该账号全部旧会话。已有终端连接失去相应授权后不能继续输入。终端 attachment ticket 仍由服务端短时签发，浏览器自动获取。撤销后尚未使用的 ticket 也无法建立写连接。
3. **升级与脚本兼容。** 建议新安装直接启用本地账号。对升级前已有账号、自动生成的 Token 文件或显式 Token/passcode/trusted 配置，分别处理。已有账号保留。仅有旧式凭据的安装保留原访问方式，由本机操作者显式迁移。迁移时可选择沿用初始密码或直接设置自定义密码。迁移成功后以账号为浏览器入口，停用旧浏览器链接及旧会话，处理浏览器已缓存的 Token。需要非交互调用的操作者可独立显式配置 API Token，沿用受控动作权限。日常浏览器登录不产生此类凭据。受管绑定优先于所有本地兼容选项。这样升级一台原本用随机秘密保护的在线节点时，不会自动增加一组公开可知的可写凭据。
4. **启动与观测。** `install.sh`、`zf web`、`tools/start-webkanban.sh` 都进入同一套认证模式判定。新账号模式下只打印普通访问链接。建议新账号模式下脚本单独启动时也默认监听回环地址，保留显式 `--host` 和已有环境配置。当前两个脚本用项目列表探活，改用最小就绪响应。现有 `/health` 含本地路径及诊断信息，应保留给已授权调用，另提供或裁剪匿名探针。密码、会话和授权链接不得进入日志、URL、遥测和 Controller 上报。

## 5. 验收场景

| 编号 | 操作 | 可观察结果 |
| --- | --- | --- |
| AC-01 新装登录 | 在空 workspace home 安装 standalone，断开外部网络后打开本地 URL，先用错误密码，再用 `zaofu / zaofu` | 错误凭据无法进入。正确凭据登录后显示首次设置。若入口是已有项目的深链接，完成或跳过设置后回到该项目。URL 和安装日志里没有访问凭据。 |
| AC-02 写权限 | 在启用 Agent 和终端的项目发送一条会产生工作区写入的请求，在 Web Terminal 输入一条可核对输出的命令 | 在项目内观察到预期写入及终端回显。欢迎向导、项目接入和两类写操作都不弹出 Token 对话框。显式只读启动后同样操作由服务端拒绝，项目无变化。 |
| AC-03 改密与退出 | 两个浏览器分别登录。其一退出并尝试复用旧会话，随后由另一会话改密。重启并重复安装到同一 home | 退出仅撤销该会话。改密后旧密码、改密前的各会话及其终端写连接失效。新密码在重启后仍可用。另一个一直未改密的新安装仍能用默认凭据。 |
| AC-04 登录边界与探活 | 未登录直连项目列表、Session、写 API、事件流和两类终端连接。以其他站点来源尝试浏览器写入，再运行安装就绪检查 | 私有数据不可读，写入及终端连接被拒。跨站写入无副作用。安装就绪检查成功且不暴露项目、路径或会话数据。 |
| AC-05 既有安装 | 用旧版生成的 Token 文件和显式配置分别建立夹具，做就地升级、重复启动、显式迁移，再复测旧授权链接及自动化调用 | 升级不重置密码、不静默扩大访问。迁移后旧浏览器凭据失效。独立显式配置的 API Token 仅在允许的接口生效。 |
| AC-06 安装与网络 | 分别经默认监听、本机反向代理及显式 `--host` 地址访问新装实例 | 安装中无需选择网络类型。三种入口均能保留默认密码并完成正常登录。改密入口可用，HTTPS 下会话 Cookie 带 Secure。 |
| AC-07 注册仅上报节点 | 本地改密后注册为 `observed`，用新密码登录。观察授权上报，再暂时断开 Controller | Controller 可看到获准上报的项目、Session 与 Token 用量（使用产生过用量的样本）。断连期间本地仍可操作。恢复后 Connector 继续上报。浏览器账号和节点机器凭据互不替代。 |
| AC-08 云端身份与归属 | 用两个测试用户走注册、申请、审批流程。分别从控制台和工作台直达链接访问。再撤销其中一人的空间授权 | 待审批用户可查看进度。获准且空间就绪的用户通过 SSO 进入自己的工作台并执行获准写操作。另一人的空间不可访问。撤销后失去访问及终端写权限。受管端的本地凭据入口始终拒绝。 |
| AC-09 视觉与账号导航 | 在桌面和窄屏打开本地登录页与工作台，在没有项目的空间访问 Settings → Security → Password | 品牌和字段可见，表单可键盘提交，侧栏账号显示当前用户。两次输入的新密码不一致时留在表单。云端登录继续使用 Keycloak。 |
| AC-10 本地向导 | 从新安装登录，分别验证完成、跳过、从旧第 3 步恢复、步骤保存时会话过期及加载错误重试。另以只读模式访问同一实例，再以可写模式回来 | 本地账号模式不出现 Token 输入。Provider 选择、环境检查、进度恢复正常。可重试的读写失败不会被记为完成或跳过。只读访问不改进度。完成或跳过后换浏览器、改密或注册成仅上报节点均不重弹。整个流程未调用项目创建或注册接口。 |
| AC-11 云端向导 | 同一浏览器依次访问两个用户各自的新空间，在 A 完成向导，休眠唤醒或使用原 PVC 重建 A 后再次进入，再进入 B | 待审批时只显示申请状态。获准且实例就绪后，经真实 Gateway 读取和保存该空间的进度，全程不输入本地密码或 Action Token。A 的 Provider 选择和完成标记保留，B 独立显示首次设置。 |

实施时先用独立临时 workspace home 跑 CLI、安装、HTTP/WS 鉴权与 Connector 测试，再以 Docker Playwright 验证本地和云端用户路径。保留原始断言及脱敏截图。云端审批/撤销采用专用测试用户，真实 Gateway 联调与模拟登录的结果分别记录。
