# 活跃看板的任务事件复用

大型计划正文进入事件载荷后，每次看板重建按任务重复做全文匹配，会耗尽
源文件不变的构建窗口。后台仍拒绝跨代拼接，因而可能长期保留旧快照。

`web/projections/event_task_index.py` 保留最近一个项目和解码代次的匹配结果。
Web 事件读取器提供代次，只有任务 ID 集合、引用上限及原末行对象都一致
时才复用；追加事件只匹配新增行。轮转、替换、解码器变化与其他项目触发
重建。结果共享已解码事件，保留原有 250,000 引用上限，不保留另一份完整
事件列表，也不原地改写正在被其他请求读取的结果。

`_kanban` 同时一次性筛选全局失败和恢复事件，供各任务计算工作流提示。
普通事件仍参与任务匹配、阶段、路由和最新活动；筛选没有改变任何失败或
恢复事件的相对顺序。`tests/test_board_task_event_cache.py` 覆盖真实看板调用、
追加、替换、任务变化、全局失败恢复及引用上限。

完整快照仍通过 `dashboard_projection.rebuild_group` 的源指纹一致性检查
后原子发布。这项优化不改变调度容量、依赖关系、审批或 TaskStore 状态。
