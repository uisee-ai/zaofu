# 活跃看板的任务事件复用

大型计划正文进入事件载荷后，每次看板重建按任务重复做全文匹配，会耗尽
源文件不变的构建窗口。后台仍拒绝跨代拼接，因而可能长期保留旧快照。

`web/projections/event_task_index.py` 最多保留四个项目的匹配序号，每个项目仍
限制 250,000 个引用。读取器提供精确源指纹及解码代次：源指纹、任务 ID 集合
及引用上限一致时，可在解码缓存被其他项目淘汰后复用序号，并映射到本次读取
的事件对象。追加复用优先使用不变的解码代次及原末行对象；若解码缓存已被
淘汰，则核对完整前缀的逐行 SHA-256（序号、显式 task_id、全文匹配文本）。
只有匹配输入确实相同才复用，任何前缀差异都重建。每项目同时限制 250,000 行
摘要；缓存不保留完整解码正文，也不原地改写其他请求正在读取的结果。

`_kanban` 同时一次性筛选全局失败和恢复事件，供各任务计算工作流提示。
普通事件仍参与任务匹配、阶段、路由和最新活动；筛选没有改变任何失败或
恢复事件的相对顺序。`tests/test_board_task_event_cache.py` 覆盖真实看板调用、
追加、替换、任务变化、全局失败恢复及引用上限。

完整快照仍通过 `dashboard_projection.rebuild_group` 的源指纹一致性检查
后原子发布。这项优化不改变调度容量、依赖关系、审批或 TaskStore 状态。

## 任务阅读页的首屏

打开任务时，`GET /api/projects/{project_id}/tasks/{task_id}/record` 从所选项目的
TaskStore 读取当前任务或其归档记录，返回脱敏后的任务信息与完整合同。正文和验收条件
可以先显示。执行历史、事件、已核验交付物仍由完整详情接口提供，读取期间保留原始正文。
完整详情在同一次事件读取中匹配任务和候选交付上下文。运行摘要直接统计任务记录的终态。
通过索引批量读取事件原文时，每次查询按项目的签名配置建立一个解码器，按索引顺序读取归档与活动段。
账号迁移或会话失效时，服务端通过 `401` 和 `X-ZF-Login: required` 通知浏览器。
工作台在原任务地址重新进入登录流程，登录后回到同一项目和任务。
