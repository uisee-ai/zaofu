# 用有界实验关闭阻塞假设

当问题只能通过代码、协议或环境实验回答，而非读取已有权威资料就能解决时，
先提出最小 Spike。产品偏好由有权决定者确认；不能用技术实验替用户决定需求。

在现有未决问题/执行规格中记录：

- 要回答的一个问题、当前假设和来源，哪些 AC/叶子任务依赖它。
- 候选方案及区分它们的具体观察；已有证据足够时直接引用，不重复试验。
- time/token/尝试上限、允许的隔离环境、必要能力与 owner。
- 成功标准、失败标准、信息仍不足时的停止条件。
- 交付证据、决定及影响，明确由哪个后继读取、什么条件下失效或需重访。

例如先在隔离数据库验证一次事务中库存与流水的失败回滚；以真实后态判断，
不以“API 提供 transaction 参数”作为成功。超时或驱动不可用是未知/环境失败，
不能证明不支持，也不能解锁依赖该结论的实现。

复用当前目录已支持的 Research 或合法规划/实施叶子；没有可用能力时提出缺口。
Spike 是方法与证据任务，不新增 Task status/type、lane 或绕过计划准入。
若当前批准范围只允许规划，先给实验方案和执行前置，不擅自开展外部副作用。
需要改动已接纳图时使用受控 replan；未受影响的工作按现有依赖继续。

完成是回答问题并让后继可读取证据；实验原型不是产品实现，仍需生产代码与验收。
