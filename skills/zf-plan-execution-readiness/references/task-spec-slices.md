# 从产品规格到可验收的任务切片

Planner 形成任务前、Critic 审查序列化后的完整包时使用。沿现有 Task `contract`、
Task Map、Plan、矩阵及评审工件记录，不增加第二任务 Schema 或语义评分门禁。
Spec 是可实现、可证伪的行为合同，不由文件名、章节数、字数或测试数量定义。

## 先形成规格，再分配实现责任

从冻结来源提取目标、范围、行为和已授权约束。每条适用行为说明主体/前态、输入、
动作、后态、拒绝条件、失败不变项和恢复方式；接口补生产者/消费者及版本，UI 补
入口、反馈、状态及键盘行为。来源没有承诺的性能阈值、非目标和产品行为不得自造。
已有资料足够时引用准确正文；当前必要合同未知时明确责任与最迟决定点。

公共数据/事务/接口只保留一个权威正文。每个消费者引用同版合同及适用条款，不把
整份 PRD 复制到所有 Task，也不把下游必需规则藏在不会选读的兄弟任务里。
技术选择说明理由和约束；固定算法、类名或技术栈只有实际合同需要时才写。

切片按可演示结果、真实依赖、事务和写入所有权决定。小产品的一条完整旅程可以
由一个 Task 承担，任务内部安排早期验证步骤；不为凑并行度拆碎同一事务。
基础设施片说明服务于谁及实际可运行入口，不能冒充已经交付产品行为。

## 每个任务的阅读模板

以下是正文模板，不是新 JSON 字段清单。保留既有 Task/AC/command/decision ID。

```markdown
## Task Spec: <exact task_id>
### 本片结果与边界
完成后能够演示什么；本片负责什么、引用哪些共享合同、不负责哪些相邻行为。
### 来源与共享合同
本次冻结来源的精确位置；共享数据/接口/事务合同的同版章节及消费者约束。
### 行为与失败
输入和前态 -> 动作 -> 后态；拒绝条件、失败必须保持不变的内容及重试结果。
### 接线与依赖
实际入口、上游已提供的行为/产物、独占写入范围；沿 Task Map 不另造路径所有权。
### 验收与早期反馈
引用具名场景、既有 AC 和命令；自检、独立 Verify、最终集成的目标和时点分别说明。
### 决定与交接
影响本片的决定 ID、责任、关闭时点；未来证据由谁产生、何时检查。
```

采用 `execution_spec` 的路线把正文放在既有 `tasks[].body.human_review.module_spec_markdown`。
无此端口时，在 accepted Plan Markdown 使用上面的精确 `Task Spec: <task_id>` 二级
标题；下属三级及以下标题归本片。共享合同可放在 `## Shared Spec` 下，任务明确引用。
这是阅读定位约定，不改变 Task 身份或准入。不得给未知 Task、重复标题或仅摘要正文
宣称“规格完整”；原文仍是审阅依据。

具名 GWT 场景只维护在当前路线既有的测试/验收矩阵中，正文通过稳定 ID 引用。
需要在人读正文展示时保持同义，不为 Preview 再造一套独立维护的场景。
路径、命令和生产者来自 Task Map；原始结果标记保留 NOT_RUN/BLOCKED，不预写 PASS。

## 一致性复核及可证伪反例

逐条检查冻结来源 → 规格 → 实际生产任务 → 场景/AC → 命令/验证责任。
同时反向检查新增约束的依据。缺 source binding 是追溯缺口，不能靠手抄原文补造权威。

- 全文决定与 `task_map.owner_decision_items` 的 ID、状态、blocking、影响任务和关闭时点
  一致。空审批问题列表不是完整登记；“两者同源”必须核对实际序列化文件。
- 输入例子可以直接作为测试数据：要求绝对 http/https URL 时写完整 URL，不能用
  `/a` 缩写又断言新增成功。保留原字符串与用于校验的解析结果的区别。
- “合理焦点”“正确错误处理”等不能独立判定的描述，应保留目标并细化可观察规则；
  未授权的产品决定明确为待选方案，不能由评审脚本猜测。
- 保存失败不仅“显示错误”，还要检查内存、DOM、持久化字节和用户输入的不变项。
- 一个任务证明局部 predicate，不能宣称下游真实事务、整条旅程或最终候选已验证。
- 读取层有内容、命令存在、引用有效和 covered 只是不同的结构事实，不能互相替代，
  更不等于 Spec 语义通过或产品测试通过。

## 独立评审与返修

作者按模板自检；配置的 Critic 必须读取同版来源和最终工件，独立指出具体反例。
在既有 review/execution_readiness 工件分别记录：规格充分性、跨工件一致性、任务
可执行性、授权/未决边界、产品验证状态；每项给正文位置、依据和未覆盖范围。
缺陷注明影响任务和最小修订，区分本次新增、历史已知、非阻断建议；不凑问题数量。
字段齐全或模板遵循只证明方法接线，不能代替上述语义评审。

返修保持 finding 身份，记录修复、合理驳回或仍未关闭的理由。复审实际变更及影响
合同；复用未变结论时引用版本和依据。按配置的返工上限收敛，不自行增加轮次。
规格变化通过现有受控修订及适用审批生效；不可覆写已接纳工件、反改需求迁就代码。

评估方法时保留正例与有来源的反例。新真实样例核对角色实际收到的方法、来源绑定、
任务规格及独立 verdict；模版检查和浏览器回放不得标为真实 Provider 生成验证。
