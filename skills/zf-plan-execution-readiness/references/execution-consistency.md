# 执行一致性复核

本方法供 Planner 和独立 Critic 使用。读取本轮冻结需求、task map、测试与验收矩阵、
产品验收规格及决定登记，检查序列化后的最终工件。输出放入已有 semantic_review、
execution_readiness 或 Critic report，不建立第二份 canonical task contract，
不要求 Kernel 推断业务语义。按以下顺序修订后，再做完整范围复核。

## 1. 从实际动作确定生产者

资源目录负责人只说明谁维护该资源，不证明谁实现所有使用该资源的业务动作。
对每条权限/行为用例追踪：来源动作 → 实际命令/入口 → 状态变化 → 实现任务 →
验证 owner、command 和最早执行时点。按已有 task/AC/command ID 记录追踪证据。

- 一行含“登记、调整、撤销”等多个不同命令时，拆具名子用例并保留父来源行。
  每个子用例分配实际生产者；不能只把父行整体换一个 owner。
- 纯授权 predicate 可由前置权限片验证，但断言只能覆盖 predicate。
  若用例要求请求成功、库存改变、节点推进或拒绝后业务不变，就是命令行为测试，
  需要实际处理器和数据边界；不得用 predicate/mock 冒充该测试。
- 权限动作归属变化时，同步行为规格、用例、测试/验收矩阵和全局汇总，核对旧引用。
  不以资源目录负责人自动批量赋值，不把统一字符串替换当作语义审计。
- 检查实际生产者是否是当前任务或已完成依赖。未来行为移回其生产者或保留后续
  mandatory candidate 验证；不得反向添加会成环的依赖，也不得删除早期可验证行为。

复核必须覆盖整个动作清单；不能只改被点名的几行。

## 2. 权限必须带动作和状态

对权限敏感行为建立具名组合：主体及有效身份、直接/组/继承职责、资源范围、节点状态、
动作、允许/拒绝，以及拒绝后的完整不变集。原文规定的继承和例外也要保留。

- “办理活动节点”和“修正已完成结果”是不同动作；即使操作同一资源，也不能合成
  “操作员/编辑者均允许”的一个 oracle，除非来源明确如此。
- 分别使用仅有职责 A、仅有职责 B、无职责、范围外、撤销后的最小主体进行反例检查。
  超级管理员成功不能证明职责分离成立。
- 同一组合在资源总表、动作明细、任务 AC、行为用例和最终候选验收中必须得到
  相同预期。一个正确的明细用例不能抵消另一个总表中的错误允许规则。
- 权限允许不豁免业务状态、占用、时间等约束；拒绝不能只断言 HTTP 状态码。

Critic 至少给出一个可能被错误总表放行的最小主体，说明已被哪条具体断言排除。

## 3. 本片 TDD 与最终候选分别核对

每个高复杂度片的步骤绑定具名断言、有效行为 RED、最小实现、同断言 GREEN、回归和
返工责任。逐步检查命令生产者及其全部前置，而不只查看 task 的 blocked_by。

- 本片 RED/GREEN 只运行本片或已就绪前置能提供的测试。一个 AC 同时关联当前和未来
  命令时，逐项按 owner/producer/时点筛选；不能把 AC 的完整命令列表复制进本片步骤。
- “任务接受前全部通过”只指本片责任。未来 mandatory 条款仍保留原身份和后续责任，
  不能提前要求其通过，也不能改成 waived、静态证明或删除。
- 缺文件、缺依赖、尚未实现的后续 runner 不是当前行为 RED 的有效证明。
  计划期列出未来测试是允许的；问题在于把未来测试当作当前片完成条件。
- 本地命令名正确仍不够：检查 recipe、用例 action 和断言是否要求执行未来生产者的
  业务动作。读取已存在状态可以使用明确的本片 fixture；“先执行后续绑定/调拨/报废，
  再读取”需要后续真实命令。两者分开记责，不以 fixture 代替最终动作验收。
- 中间阶段 smoke 可以声明尚未就绪范围；最终 candidate 用例必须重新从最终 AC
  推导完整输入、旅程、页签、动作与失败断言。不能沿用阶段模板中的排除语句。
- 对最终 AC 承诺集合与用例实际覆盖集合逐项比较；有差集就列明确缺口。条件能力
  只有在对应决定明确未启用时才保留条件边界，不能借用阶段排除来缩小最终范围。
- 逐项核对阶段命令、用例 `evidence_ref`、测试矩阵和 evidence contract 的收据路径。
  阶段门必须消费本阶段实际产生的结果；不能误指仅最终 candidate 命令才生成的收据。

审查同时防止两种错误：当前片依赖未来测试，以及最终用例只检查早期子集。

## 4. 修正也是完整事务

初次提交的原子性用例不能自动证明“修正已完成结果”的正确性。先列出本次命令拥有的
完整状态向量，再设计成功、非法输入、并发/撤权和逐写失败用例。

对含时间、关联、库存或衍生事件的修正，至少核对：

1. 修正前完整状态、修正请求及每个受影响实体的修正后状态；
2. 业务时间 T1→T2 时，哪些来源于本次结果的事件必须一并更新；
3. 非法顺序、位置/占用冲突、无效关联、权限撤销及任一写入失败时，完整状态向量不变；
4. 本次结果之后，由其他独立命令生成的合法事件/关联保持不变；
5. 重复请求、同 key 不同请求及丢响应重试的结果与回执；
6. 其他可独立变化的维度不能因已有库存差额等单一用例通过而被默认覆盖。

实现保持单一事务 owner，用短小片内 TDD 步骤覆盖这些维度；不能拆成多个对外可见
提交来降低任务复杂度。对应阶段集成与最终验收同步使用完整向量。

## 5. 决定与规格只使用当前版本

选择已有决定登记作为当前内容来源，检查所有 Q/decision 在 PAS、task map、矩阵、
Plan 正文及阶段门的负责人、受影响范围、最迟关闭时点、条件状态和证据要求。

- 引用可解析时引用同版条目；协议要求内嵌快照时，从当前登记重新生成完整内容并逐项
  比对。不能只同步 ID 或 status，却保留旧负责人、旧范围或旧阶段。
- 审计全部决定，不只处理本轮被点名的 ID。旧版本保留历史身份，不能混入当前快照。
- 保留未知外部决定；named owner 未知时标待指定，不能为了通过审查编造真人或答案。
  无依赖的盘点可以继续，受影响的接入与真实验收必须在对应前置关闭后进行。
- 决定改变验收责任时，同时复查 producer、依赖和阶段命令，不只修正文案。

## 6. 序列化与下游交接

在最终 Plan Package 输入上重复以上比较。确保 Impl/Verify 所依赖的行为向量、片内步骤、
决定和用例正文包含在已声明的计划输入中，或由显式、同版的受控引用提供。
不能只有无法在下游工作目录解析的相对路径。机械检查证明引用/摘要/读取路径；
语义审查证明内容充分、相互一致；二者分别记录。

检查实际消费入口，而不只检查作者目录。`artifact_refs`/`evidence_refs` 中存在文件，
只证明它被声明为产物；自定义 `semantic_input_refs` 也不会自动成为 Impl/Verify 的
受控输入。对照本轮 `required_plan_ports`、`plan_ports` 正文与下游 source manifest：
需要的规格应完整包含在已声明输入中，或使用当前协议支持、带版本约束的显式输入。
不能把“路径已写进清单”当作“正文已交给实现者”。从冻结 Package 出发，按下游真实
解析规则验证正文；测试环境不依赖 Planner 的私有工作目录，并核对工件搬移后的引用。
例如，可在已有必需的 `test_matrix` 中交付用例正文，或将规格声明为显式
`plan_ports` 并纳入 `required_plan_ports`；只新增一个未被消费的路径字段不构成交接。
同时检查序列化后每个工件是否满足实际 Package hydration、受控读取和 Preview 的
大小约束。不能把全部语义正文及重复历史副本塞入一个超限索引；按消费职责拆分具名
工件并绑定版本。低层读取函数成功不代表完整 Package 可以读取，准入预检通过也不
替代下游真实入口验证；不通过扩大公共限制掩盖规划工件的打包缺陷。
独立文件可使用 `plan_ports` 的 `{logical_name, ref, sha256}` 描述符，`ref` 指向作者
工作目录内的文件，并声明相应必需端口。Kernel 搬移显式描述符并保留摘要校验；
不自动重写任意 JSON 正文中的业务路径，也不允许作者自行写 canonical 状态目录。

每个旧 fix_item 记录修订位置与反例排除依据，再说明当前完整审查范围和未覆盖项。
Planner 不能自批；Critic 不因任务、用例或矩阵计数增加就判通过。计划通过只表明允许
后续按合同执行，不证明产品已经完成、TDD 已实际运行或外部接入已验收。

## 最小反例集

| 候选写法 | 应如何判断 |
| --- | --- |
| 权限基础片只验证授权谓词，后续命令片验证真实事务 | 可接受，需分别写清两个断言的边界 |
| 资源管理片声称完成后续业务操作及失败回滚 | 不接受，实际动作生产者或验证时点错误 |
| 仅编辑职责允许完成活动节点，来源只允许操作职责 | 不接受，即使另一个明细测试写对 |
| 当前片步骤执行依赖当前片的最终集成测试 | 不接受，验收依赖倒置 |
| 阶段读取检查子集，最终用例覆盖全部已承诺旅程 | 可接受，必须独立核对最终集合 |
| 最终用例复制阶段的未覆盖范围 | 不接受，最终 AC 与断言范围不一致 |
| 修正仅测试某个数量差额，其他时间/关联变化未定义 | 不接受，单一维度不能证明完整修正 |
| 不同工件引用同一决定 ID，但关闭时点不同 | 不接受，ID 一致不等于语义版本一致 |
