# 最终包对账：一次形成可复核结论

供 Planner 自检和独立 Critic 使用；实际重新读取已序列化的最终候选，不能以作者声明、
模板存在或结构校验代替语义审查。结果进入现有评审工件，不新增 schema、角色或 gate。

## 对账顺序

| 检查 | 必须核对的关系 | 典型反例 |
| --- | --- | --- |
| 来源与范围 | 原始输入 → PRD → Plan/Task；优先级、mandatory、交付时点、非目标和定性约束 | P1 必需被改为可选；每片用法被加强为每片 README |
| 行为与验证 | 原子场景 → AC → 实际生产任务 → 命令/owner/证据路径 | 一个谓词检查冒充完整事务；矩阵遗漏失败后状态 |
| 本片与后继 | 当前命令所需产物由本片或已完成依赖生产；保留后续 mandatory 验证 | 首片要求执行尚未生产的最终脚本；为消除阻塞删除最终验收 |
| 决定一致性 | 全部决定的 ID、status、blocking、负责人、范围、最迟时点和关闭证据在最终包同义 | 同 ID 在正文已关闭，在 Task Map 仍待确认；批准选型被写成验证已完成 |
| 接手可执行性 | 本片规格或具体共享引用中可取得准备、清理、写入责任、RED/GREEN、独立验证 | 整个 Plan 复制到任务；义务藏在无引用兄弟任务；证据路径无写入者；唯一写者可选生产而后继必需消费 |
| 修订保留 | 新旧行为、直接/间接消费者、旧证据适用性和未变场景 | 修改共享错误规则只改一个入口；摘要未变就复用不同目标运行证据 |

TDD 写具体失败断言、触发前态及同一断言的 GREEN 方法；未运行仍为 NOT_RUN。
来源引用不得用方法文件替代产品要求。错误必须绑定实际解码后的内容及可复现依据，
不凭 JSON 转义外观判定命令错误。工具响应的 `content` 可能再次包装 JSON；先还原字段字符串，
再给出实际字符或 argv 依据。仅检查序列化与语法不代表尚未实现的 runner/产品已通过。
没有缺陷的正例应通过，不凑 finding 数量。

从原始用户输入单独摘录限定范围的原句，再与 PRD/最终 Task Map 对账；不能只检查
后两者互相一致。尤其保留明确任务数、顺序、mandatory/优先级、用法和最终文档的
不同交付时点。用户明确“两任务”时，测试布局/共享 helper 归实际首片，不能为避免
共享路径冲突加第三个脚手架任务；确需改变须提出具名取舍并取得对应授权。
“各片用法 + 最终 README”不能改成“每片修改 README”；后者可能制造额外路径冲突。
来源版本确有冲突时列出原句、版本和授权依据，不静默取更严格或较近的转述。

逐任务读实际 mandatory AC 原句，不能只看命令 owner 或模块正文。首片只交付读取，
却要求实际执行两入口，或无文档写权/已交付生产者却强制验收最终 README，属于阶段冲突。
若首片明确拥有 README，则可先生产两种既定语法并标明后继未交付；文档内容检查不等于
运行未来入口。当前只执行本片，完整双入口的实际执行义务保留在后继及候选验证中。

决定对账先分别列出正文 Decision Register 与 `task_map.owner_decision_items` 的完整
ID 集合，再逐 ID 核对状态及义务；在现有评审中记录两边位置与缺失 ID。
正文有 D-01/D-02，而 Task Map 为 `[]`，即使作者解释“没有新增产品取舍”也不通过：
该数组是完整登记，包含已确认、待审工程方案和待验证记录；角色 control result 的
本次行动问题列表才可以为空。只核对共同 ID 会漏掉整条缺失，不能据此声明全部一致。
审批 gate 如出现在正文登记，也必须保持同一身份和原始状态；不把登记本身当作授权。

## 一个问题只登记一次

在现有 findings/review 中保持稳定 `id`，绑定当前候选 digest、来源原句、冲突字段、
最小反例、受影响消费者和关闭条件。分类为已复现产品失败、规格矛盾、证据缺口或
未证实疑问；缺证据可阻塞，但不得伪称产品已失败。没有缺陷的正例不凑问题数。

先还原实际字段再核实阻塞问题：JSON 解码/路径/摘要/语法检查可交给受控工具，
保留实际字符或 argv 与最小复现；序列化外观不是缺陷证据。原 finding 错误时，以
原 ID 记录 withdrawn 和反证，不要求作者虚构修复。换格式或措辞而行为未变不关闭
真实问题。作者修复声明与独立 Critic 的 closed/仍开放判断分开，禁止作者自批。

修订先核对旧新候选身份和影响闭包，再逐 ID 处理全部开放项与未审项；记录本次读到
的范围和未覆盖限制。`plan-rejected-review` 只携带经核验的旧 rejected 事实，不能
当成批准或当前理解。当前候选和 authority 仍按强制输入独立审查；已批准局部修订
只有运行时确实给出 scoped 必读策略后才能按其选择读取，均允许受控展开。

同一候选、同一问题反复出现时，给出未收敛原因及剩余反证，沿既有恢复/人工路径
处置；不增加默认投票 Agent、返工轮数或自动批准。仅查询缺失事实，不反复读取
全量帮助或相同正文；分页按返回范围连续读取，截断不能冒充全文。

## 交接评估

让未参与作者输出的读者回答目标/非目标、任务顺序、每片完成条件和现在阻塞事项，
并从来源说明答案；记录澄清与误解。独立 Agent 结果与真人理解时间分列。
用固定正例与单缺陷变体校准遗漏、优先级、时点和共享修订判断，保留误报与漏报；
模型评审通过不能替代产品反例测试或真实实现后的验收。
