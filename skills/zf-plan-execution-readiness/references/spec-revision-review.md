# 规格修订与审查影响

用于来源更正、Owner 决定、设计合同修改或局部返修。先绑定当前有效 authority、
Plan Package 与待评候选版本；历史批准和测试收据保持原身份。文件更新时间、代码
已合并、Judge 通过或历史 `spec.promote.completed` 标签都不能替代变更授权与正文。
当前自动 Judge 回调不生产规格更新，`promotion_not_verified` 也不表示已排队同步。

## 从发现到新的有效规格

1. 区分产品意图变化、实现策略变化、任务重排、实现缺陷和纯文字修正。
   实现行为只提供证据；没有授权时，不能反写规格使已有代码自动合格。
2. 引用实际授权来源和决定；已有授权足够时继续，不重复索要相同批准。
   未授权提议保留为候选，点名受影响动作，无关前沿可继续。
3. 保留旧新来源/AC/决定/合同映射、改变理由和剩余 mandatory 义务。
   通过当前受控修订、独立 Critic 及适用审批生效；不原地改冻结工件。
4. 已完成任务仅在原证据对新目标仍适用时复用；不直接修改 Task 状态或抹掉旧结果。
   需要新增实现时交给既有 gap/replan 路径。旧证据保留历史价值，不代表新目标通过。

## 在既有评审工件中交付影响记录

沿来源 → 行为/设计 → 生产者/消费者 → Task/命令/证据检查变更传播。
记录本次实际读到的正文、采用的版本和未覆盖范围；按需要使用下表。
表内类别只是评审语言，不是新 schema、verdict 或调度状态。

| 变更与依据 | 影响项及理由 | 旧结论 | 本次处理与证据 | 剩余义务/责任 |
| --- | --- | --- | --- | --- |
| 来源/决定 ref、旧新含义 | 合同、消费者、Task、AC、命令的稳定 ID | 旧包/评审/收据 ref | 重审、可复用及依据、或尚不能判断 | owner、最迟关闭时点与允许继续范围 |

重审依赖关系，不只重审被点名的段落。例如幂等约定变化会影响超时未知结果、
提供者重放/冲突、消费者重试和 UI 反馈；按实际合同确定范围，不机械要求所有项目
都有这些组件。依赖没有变、证据目标相同且旧审查可追溯时，可以给出复用理由。
只有相同 ID、相同标题或文件摘要未变，不证明引用它的新语境仍然成立。

分别标明复用的是规范审查结论还是运行收据。例如未变的列表权限规则可以复用旧
语义审查，新候选的列表运行仍须有现有准入规则允许的 current 证据；不能把
“规则无需重审”写成“新候选测试已通过”。是否重跑由实际目标和证据适用性决定。

需求质量问题也记录新通过、退化、仍未关闭和未审项。检查规格是否明确了适用的
输入、状态、异常和可观察判据；这里的“通过”仅指规格质量，不是实现通过。
未知不是失败证据，更不是通过。拼写/链接修正无需臆造行为变化；若实际上改变
了合同引用对象，则按该对象的语义和授权重新判断。

将影响摘要、审查范围和关键未决项写入本版 Plan 的人读正文，让现有 Preview 可读；
完整依据放在当前协议支持的评审工件/端口中并绑定 ref/digest。未被消费者读取的
自定义路径不能充当交接。沿用前版结论时，引用确切版本并列出复用边界。

## 可证伪的检查

- 修改共享合同后，能沿实际消费者找到仍引用旧规则的验收或测试。
- 纯编辑修订可以复用仍有效的结论，不自动触发全产品重新实施。
- 所有任务已完成但新目标缺证据时，保留旧成果并提出有界增量。
- 用户未授权的新行为、尚不可用的服务或未读输入保留明确限制，不自填答案。

判断依赖闭包的语义充分性由 Planner/Critic 负责；运行时已有摘要、currentness、
合同差异与审批校验继续负责机械边界，不增加按关键词计分的自动质量门禁。
