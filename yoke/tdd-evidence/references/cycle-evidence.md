# Impl 内部的 RED / GREEN / REFACTOR

先读当前 Task 合同、规格和真实消费者，选择最低但能观察目标行为的测试边界。
每个有风险的行为使用具名测试，勿把一段通用 TDD 文案复制为所有 AC 的证据。

| 步骤 | 执行与保存的证据 |
| --- | --- |
| RED | 实现前基线 + 测试补丁/文件摘要 + 原样命令 + 预期失败 + 实际退出码/输出引用 |
| GREEN | 最小实现 + 相同测试命令的通过结果 + 实现版本 + 受影响调用者/共享合同回归 |
| REFACTOR | 有必要才做，说明保持不变的行为；清理后在最终版本重跑受影响验证 |

证据保存在已有实现总结/sidecar，通过当前协议绑定 task、attempt、generation、
target/tree 与命令。RED 和最终 GREEN 面向不同树，不能把历史 GREEN 当最终收据。
命令写清 cwd、环境前提与实际参数；证据摘要引用完整输出，不只写“全部通过”。

## 失败与首跑即绿

- 缺依赖、服务不可达、拼错命令、collection error 或错误 fixture 先归类为环境/
  测试问题。修正后重新观察目标断言，不能将它们当成功的功能 RED。
- 新测试首跑即绿：检查是否行为已实现或断言无效。行为已存在时保留测试作为
  回归证据，报告“未观察到 RED”；不必添加无意义实现，也不改坏产品制造失败。
- Bug 修复先复现；当前版本无法复现时记录输入/版本/环境及差异，不能声称已修复。
- 纯文档或无行为变化的改动可说明不适用；配置若改变行为仍需对应行为验证。
- 不通过删断言、skip、xfail 或放宽验收让 GREEN 成立。`expected_red` 等运行时
  验收选项遵守原合同，不能为了开发阶段的失败批量修改。

## Verify 如何独立复核

先核对当前 wrapper、验证 owner 和目标身份，再审测试是否能观察规格结果。
必要时在隔离临时工作区将测试补丁应用到 RED 基线复现，绝不回退共享工作区。
机械命令已存在且允许复用的收据，按当前策略核验目标、digest、owner 和有效性；
禁止复用、缺失、过期或需要独立产品观察的证据则实际执行。
独立性来自独立判断与受绑定的证据，不来自无条件重跑相同命令。

局部 GREEN 不覆盖后续任务产生的行为。将跨任务验证保留给 Candidate Verify，
失败点名具体行为和返工 owner；Judge 只消费已接纳的当前证据，不接管 TDD。
