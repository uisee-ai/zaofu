# 独立发现与逐项分诊

先读本次原始需求、完整 AC、目标版本及代码/测试，形成自己的失败假设和探针，
再用实现者总结核对遗漏。作者说明是待核查的主张；它不改变验收分母。
若 briefing 已包含作者结论，如实记录已暴露，仍从入口和断言重新验证，不宣称盲审。
不为此跳过 required read、隐藏必要需求，或额外启动未经授权的 reviewer。

在当前报告正文或已允许的 evidence sidecar 中保留原始发现，再填写既有 gap_findings：

1. 每个发现给局部 ID、来源、具体主张、文件/入口和 AC；先不合并相似措辞。
2. 验证触发状态是否可达、上游 guard 是否排除它，沿真实消费者检查。
   同一文件上的另一个缺陷或相近主张，不能替代本项验证。
3. 记为已证实、已反证或未决，并附探针/代码证据；未决说明缺什么证据。
   只有测试数量少、覆盖率低或作者说已测过，都不足以作出缺口结论。
4. 对已证实问题按一次发生的实际损害判断，映射现有 Critical/必改/Nit/Consider。
   罕见不等于无害；修复困难不增加严重性。无具体损害的个人偏好不触发返工。
5. 最后按同一根因归并，保留原始 ID 和驳回理由；每个阻断项给最小修复范围和验证。

这是语义审阅记录，不增加 schema 枚举或第二份 verdict。未决问题若使 mandatory AC
无法证明，则报告证据缺口；没有证据时不能宣称存在产品缺陷，也不能宣告验收通过。
读取失败、探针没运行和实际检查无发现分别说明；不能以“零 finding”掩盖未检查。

复核历史驳回时，只有主张、触发路径及相关版本仍一致才可引用原理由。
代码或前置改变后重验；不得因“上次说过”永久忽略一个重新出现的真实缺陷。
